# r18 回应 + IDDR 双沿实测计划（榨干 SWO 带宽）

> 目标（明确）：**追平甚至超越 ORBTrace 的 SWO 带宽（62Mbaud NRZ / 48Mbit Manchester），
> 把这颗 F429 的 SWO 榨到最后一滴。** r18 红方对"目标该不该追"持反对意见，但本文聚焦
> "如何用实测榨干"，并先诚实接受 r18 在方法学上的正确部分。

---

## 1. 诚实接受 r18 对的地方

| r18 论点 | 接受程度 | 说明 |
|---------|---------|------|
| Q1 真实指标是"每 symbol 采样数"，非绝对采样率 | **完全接受** | 这是我原分析的根本错误：把"等效采样率 2.5×"当成"baud 可达 2.5×"。脉宽测量的裕度由"采样数/bit"决定。 |
| ORBTrace 62M@500MSa/s = 8.06 采样/bit，与我们 21M@200MSa/s 的 9.5 同档 | **接受算术** | 提 IDDR 到 500MSa/s 时 baud 也按比例提，采样数/bit 几乎不变 → **不能简单线性外推到 62M 干净**。 |
| GPIO Fmax 90M 是纸面翻转极限，非杜邦线眼图 | **接受** | 实际墙是 SI，不是引脚 Fmax。 |
| ISERDES 对 F429 用不满、复杂度被低估 | **接受** | F429 阶段删掉 ISERDES，纯理论。 |
| 纯软件外推不可信 | **实测接受** | 我试了两个理想调制模型，都有 bitlen 取整假象（整数采样数干净、非整数碎，非物理）——**软件无法可信判定 8/bit 是否干净，必须上真硬件。** |

## 2. 但 r18 也有一个未经实测的论断（分歧点）

r18 Q1 结论："**21M 已接近脉宽测量在 ~8 采样/bit 的固有上限，没有 2.5× 提升空间。**"

这是**推断，不是实测**。已知的真实数据点只有两个：
- 21M = **9.52 采样/bit** → 干净（0.28%）
- 28M = **7.14 采样/bit** → 碎（I-sync 6 字节包系统性损坏，单字节 P-header 大多还对）

**碎点在 7.14~9.52 之间，而 IDDR 目标 56M=8.93/bit、62M=8.06/bit 都落在这个区间内。**
r18 赌"碎点≈9，所以 8 也碎"；我赌"碎点可能≈7.5，那 8.06/8.93 还在干净区"。**谁对只能实测**——
而实测恰恰需要做 IDDR（或提时钟），因为：
- 200MSa/s 单沿无法在 8 采样/bit 处取到干净数据点（28M 已是 7.14 且碎，21M 是 9.5，**中间的 8/bit 对应 ~25M，200MSa/s 取不到这个整数 bitlen 的好点**）。
- 必须把采样率提上去（IDDR 500MSa/s 或 MMCM 提频），才能在 8~9 采样/bit 处用**更高 baud**取到真实数据，画出真实碎点曲线。

## 3. 28M 碎法的真实证据（决定性，指向"可榨"）

真实 28M 数据（7.14 采样/bit）激进重锁解码：
- unknown **仅 1.2%**（单字节 P-header 大多正确 → per-bit 错误率低）
- 但 **I-sync 总数 = 0**（6 字节 I-sync 包必有一字节错 → 锚点全灭）

**含义**：28M 不是"采样全崩"，而是"per-bit 错误率到了几个%，单字节扛得住、6字节包扛不住"。
这说明 **7.14/bit 是临界边缘而非悬崖**——往上加一点采样数（8~9/bit）很可能就把 per-bit 错误率
压回锚点能存活的水平。**这正面支持"8.93/bit(56M IDDR) 可能干净"的可能性**，与 r18 的悲观判断
相反。但仍需实测确认。

## 4. 实测计划：IDDR 双沿过采样前端（榨干第一步）

r18 Q2 正确指出：我们现有 `trace_capture_a7` 的 IDDR 是**源同步**用法（TRACECLK 当采样钟、
IDELAY 对眼），而 SWO 要的是**过采样**用法（自由跑的高速钟双沿采异步单线、不用 IDELAY 对眼）。
所以这是**新写一个过采样 IDDR 例化**，不是"复用现有"。计划：

### 4.1 RTL
- 新 `swo_iddr_capture.v`：SWO 单线 → IBUF → IDDR（C = 250MHz 自由钟，DDR 双沿）→ 每周期 2 个
  采样位 → 喂改造的 `swo_pulse_capture`（吃 2 采样/周期，对齐上游 `PulseLengthCapture` 的 `In(2)`）。
- 采样钟 250MHz 由 MMCM 出（占空比须严格 50%，r18 Q2 提的新约束，MMCM 默认满足）。
- IDELAYCTRL 仍按 200MHz 喂（若保留 IDELAY 旁路）；但过采样不依赖它，可不接。

### 4.2 等效采样率
- 250MHz × 2（IDDR 双沿）= **500 MSa/s**，与 ORBTrace 同档。
- 若 MMCM 能稳定出更高（如 300MHz×2=600MSa/s），裕度更大。

### 4.3 实测扫描（用真硬件回答 r18 Q1）
STM32 SWO 设 ACPR 扫：28M / 42M / 56M / 84M（HCLK 整数分频点），每点：
- 记录 **采样数/bit**（500MSa÷baud）、**unknown%**、**flash 锚点数**、**I-sync 总数**。
- 画 "采样数/bit vs 锚点存活" 曲线 → **实测碎点**。
- 与 LA 金标准对拍（同一固件，proj_add.axf 已知 PC），判 SI 是否先于采样裕度成为墙（r18 Q3）。

### 4.4 判据（诚实预设，避免事后找补）
- 若 56M（8.93/bit）锚点存活、PC 命中真实地址 → **追平 ORBTrace 56M，r18 Q1 悲观判断被证伪。**
- 若 56M 碎但 42M（11.9/bit）干净 → 实测上限 42M（已超 21M，但未到 ORBTrace 62M）。
- 若 LA 金标准在 56M 眼图就塌（SI 先到墙）→ r18 Q3 对，瓶颈是 SI 非采样，记录线缆改善方向。

## 5. 对 r18 战略反对的回应

r18 Q6："SWO 再快也是 stall 节流，非项目要的满速实时，且并口命门没解。"

- **接受"SWO ≠ 满速实时"**——并口仍是满速 trace 的正解，SWO 是省线束的旁路。
- **但榨干 SWO 带宽有独立价值**：① 省线束场景下，baud 越高 = stall 拖慢越少（56M 比 21M 让 CPU
  快 ~2.7×），对"产品上用 SWO 抓长 trace"是实打实的可用性提升；② 这是把 A7 采集能力相对
  ORBTrace 定标的唯一硬指标，做出来才知道我们的平台到底强在哪。
- **优先级**：与并口 SI 命门**并行**，不互斥（IDDR 前端是独立 RTL，不动并口路径）。

---

## 6. 一句话

r18 在方法学上对（采样数/bit 是真指标、纸面外推不可信、ISERDES 删掉），我接受并改正。
但"21M 已是固有上限"是 r18 的**推断**，真实碎点（7.14~9.5/bit 之间）只能实测。
**IDDR 双沿 500MSa/s 前端就是那把尺子**——它既是追平 ORBTrace 的手段，也是回答
"SWO 还能不能榨"的唯一实测途径。先搭它，用真硬件 + LA 金标准把碎点钉死，让数据说话。
