# 32 - 板载逻辑分析仪（DDR3 缓冲）与解码器对拍设计

## 动机

FPGA trace 链路调试长期的痛点是**定责难**：抓不到 PC 时，无法快速区分是

1. **采样错**（引脚信号本身有问题 / IDDR 相位错 / 字节错位），还是
2. **解码错**（TPIU 去帧 / ETMv4 mortrall 逻辑 bug）。

proposal 30 的 dbg_regfile 已能回答"引脚有没有信号"，但回答不了"采到的**每一个
字节**对不对"。用户想在 FPGA 里嵌一个逻辑分析仪，把原始采样存板载 DDR3，用来
**与 PC 端解码器对拍**（cross-check），并顺带评估能否做成一个采样率超过手头
100MHz 外部 LA 的板载示波器。

本文基于 A7-Lite 板级实测资料（共享目录 `A7_Lite/`）给出 ROI 评估与设计。

## 采样率评估：能否超过 100MHz 外部 LA？

分两种工作模式，二者 ROI 与目的完全不同：

### 模式 A：异步过采样（与外部 LA 同类，可比"采样率高低"）

FPGA 用自由运行时钟对 trace 引脚过采样，存 DDR3——这就是一台板载逻辑分析仪。

- IDDR + 400MHz fabric 双沿 = **400-500 MSa/s/lane**（本项目 SWO 支线
  `swo_iddr_capture.v` 已实测 200MHz IDDR → 500 MSa/s 过采样，技术验证过）。
- ISERDES 过采样模式理论可达 1.25 GSa/s/lane，但需差分/对管脚，5 条单端 trace
  线用 IDDR@400-500MSa/s 更现实。
- 5 lane（1 clk + 4 data）× 500 MSa/s = **2.5 GSa/s 聚合**。
- 存储：5 lane × 500MSa/s × 2bit(DDR)/8 = 625 MB/s 原始位流 → 打包后 <1600MB/s
  DDR3 带宽内，512MB 可存 **~0.8s @ 625MB/s**（远超一次 trace burst 需求）。

**结论：模式 A 采样率 400-500 MSa/s，是手头 100MHz LA 的 4-5 倍**，且深度
（512MB）远大于外部 LA 的样本深度。对"看清 12.8M TRACECLK 的边沿抖动/占空比/
建立保持"绰绰有余。

### 模式 B：源同步对拍（真正的高 ROI 用法）★

不过采样，而是**把现有采集链 `trace_capture_direct` 采到的字节流原样落 DDR3**，
每字节附 TRACECLK 周期序号。价值不在"采样率高"，而在：

- 与 PC 解码器吃的是**同一份字节**（bit-exact），可逐字节对拍：PC 报"某处
  unknown"时，回放 DDR3 里那段原始 nibble，立刻分清是采样错位还是解码 bug。
- 相当于给 `trace_capture_direct` 加了一个**片上黑匣子**，配合 proposal 30 的
  sticky first-error，把"哪一字节、哪一时刻、什么错"一次性锁定。

对拍模式等效采样率 = 2×TRACECLK（源同步、零抖动），不与外部 LA 比高低，而是
提供**零歧义 ground truth**。

## ROI 判定

| 模式 | 目的 | 成本 | ROI |
|------|------|------|-----|
| **B 源同步对拍** | 定责采样 vs 解码；片上黑匣子 | 低（复用采集链 + 一个 DDR 写通道 + MIG） | **高，建议先做** |
| A 异步过采样 LA | 板载示波器，看 SI/边沿/抖动 | 高（第二组过采样引脚 + 触发逻辑 + MIG） | 中，加分项 |

**主要一次性成本是 MIG（DDR3 控制器）集成**：约占 30-40 个 I/O、需 200MHz 参考
时钟（50M→MMCM）、约 5-8% XC7A35T 逻辑 + 1 个 MMCM。MIG 一旦跑通，A/B 共用。

判定：**值得做，先做模式 B**（解决长期定责痛点，成本低）；模式 A 作为后续
可选增强（当需要正面排查引脚 SI 且外部 LA 不够快时再上）。

## 设计（模式 B 优先）

```
                     ┌─────────────────────────── FPGA (XC7A35T) ──────────────────────────┐
 STM32 ETM 4bit  →  trace_capture_direct  →  cap_byte/cap_valid ─┬─→ AsyncFIFO → UDP (现有实时路径)
 (TRACECLK 任意)     (IBUF→BUFG→IDDR)         + period_seq        │
                                                                 └─→ la_ddr_writer → MIG → DDR3 (512MB 黑匣子)
                                                                          ▲
                                          触发/使能 (CSR :5002)  ─────────┘
                                                                 读回: la_ddr_reader → UDP :5556 → PC 对拍
```

### 新增 RTL

- **`la_ddr_writer.v`**：clk90(=trace)域把 `{period_seq[?:0], cap_byte}` 打成写
  突发，跨到 MIG UI 域（200MHz），环形写入 DDR3。带 CSR 使能 + 触发（可由
  proposal 30 的 first-error 事件硬件触发，抓"出错前后 N 字节"）。
- **`la_ddr_reader.v`**：读回环形缓冲，经独立 UDP 端口（:5556）流回 PC，避免与
  实时 trace 流(:5555)争带宽。
- **MIG 例化**：用板载 `mig_ddr3.xdc`（400MHz），50M→MMCM→200M sys_clk_i。
- **对拍脚本 `la_crosscheck.py`**（PC）：把 DDR3 回读的原始字节喂
  `mmcm_stream_orbetto` 同一条解码链，与实时 :5555 流做 byte-diff + 解码 diff，
  输出"第一处分歧的字节偏移 + 该处 nibble"。

### 触发模式

1. **软件触发**：CSR 写 → 立即开始环形录制 N 字节。
2. **错误触发**（高价值）：接 proposal 30 的 `first_err` 脉冲，硬件自动冻结
   环形缓冲，保留错误前后窗口（类似 ILA 的 trigger position），PC 事后回读。

### 实施阶段

- **P1**：MIG 例化 + 自环 write/read 通（不接 trace，先证 DDR3 通路，类似
  stage3 net_test 的做法：一个已知 pattern 写入再读出比对）。
- **P2**：接 `trace_capture_direct` 落黑匣子 + :5556 回读 + `la_crosscheck.py`
  byte-exact 对拍。
- **P3（可选）**：模式 A 异步过采样前端 + 触发，做板载 LA/示波器。

## 风险与备注

- MIG 校准（`init_calib_complete`）失败是 A7 板常见坑；P1 自环先隔离。
- DDR3 引脚是 SSTL15 固定 bank，不与 trace/RGMII 冲突（`mig_ddr3.xdc` 用 bank35）。
- 若 MIG ROI 偏高、只需短窗口对拍：**降级方案**是先用片内 BRAM（225KB）做小黑
  匣子（够存 ~200KB 原始字节 ≈ 当前一次抓取的头部），零 MIG 成本先把"对拍"能
  力落地，DDR3 深缓冲留到确有长窗口需求时再上。

### 排障中定位并修复的关键 bug（均已板级验证）

1. **DDR3 写数据相位**（P1）：厂商 `ddr3_wr_ctrl` 当拍组合采样 `app_wdf_data`，
   registered 赋值晚一拍 → 存的是前一个 word。改组合逻辑。
2. **复位跨域**（P2a）：sys_rst 在 clk100 域驱动 clk125 MAC-FIFO 复位，
   recovery check 失败。复位同步器移到 clk125 域。
3. **多比特 CDC 撕裂**（P2a）：32-bit 计数器裸 2FF 同步读到乱值 →
   toggle 握手原子快照。
4. **self-TX 截断 wedge**（P2b-2）：中途放弃 UDP 帧卡死 udp_complete +
   :5001 echo。改为补零凑满包（有限流不能截断 UDP 帧）。
5. **reader 溢出**（P2b-2）：读 800MB/s 灌爆网络出口 12.5MB/s 的 FIFO →
   按 FIFO 空间节流每个突发。
6. **冷 ARP**（P2b-2）：reset 后 FPGA 无主机 MAC，self-TX 发不出 →
   la_readout 先 :5001 预热 ARP。
7. **DDR3 突发内地址不递增**（P2b-3，与 #1 同类）：writer/reader 在 64-word
   突发内 app 地址恒定 → 全部命中同一地址 → 读回是最后一个 word 重复 64 遍
   （period-16）→ 解不出 PC。改为每命令 +8（4:1 PHY 一 word = 8 列地址）。

### 可观测性设施（proposal 30 复用 + 增强）

- **BUILD_ID 寄存器（0xFF70）**：每次构建打入 Unix 时间戳，:5001 读回证明
  运行的 bitstream == 最新构建，排除"烧录/冷启动没生效"这类低级错误。**极其
  有效**——多次帮助排除虚假故障方向。
- 黑匣子状态页 0xFF5x（magic 0xB0）+ reader FSM/words 观测 0xFF60。
- `fpga_health.py <ip> blackbox`、`la_readout.py` 全流程脚本化。
- 附带发现：`openFPGALoader --reset` 可靠地从 flash 重载 + MIG 重校准，免手动冷启动。

### 遗留优化项（非通路正确性问题）

- 提高真 trace 占比（当前窗口含较多 idle filler，稀释 A-sync 密度）。
- 全 4MB 解码（Python parity 搜索慢，需固定 parity/order 或加速）。
- 严格"黑匣子 vs 实时 :5555 流" byte-exact 对拍（需顶层同时含实时流 + 黑匣子）。
