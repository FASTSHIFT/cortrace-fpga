# 提案 26 — 频率自适应采样方案设计

> 日期：2026-07-04
> 状态：设计阶段
> 关联：proposal 22（MMCM 采样）、proposal 12（deskew 方案选型）、proposal 25（满速验证）
> 触发：当前 MMCM 方案每换一个 TRACECLK 频率都要重综合比特流（MULT/DIVID/PHASE 固化），无法满足产品形态需求

---

## 问题定义

当前 `trace_capture_mmcm` 架构的限制：

| 参数 | 性质 | 影响 |
|------|------|------|
| MULT/DIVID | 综合时固化 | 决定 VCO 频率，换频率必须重综合 |
| PHASE | 综合时固化 | 决定采样相位，最优值随频率变化 |
| CLKIN_PERIOD | 综合时固化 | 告诉 MMCM 输入时钟周期，影响 DRC |

实测数据（proposal 25）：

| TRACECLK | 最优 PHASE | unknown% | 备注 |
|:---:|:---:|:---:|:---:|
| 21 MHz | 90.0° | 0.002% | 黄金 |
| 42 MHz | ~90° | 2.95% | 未细扫 |
| 84 MHz | 117.0° | 2.57% | 今日扫出 |

**目标**：一个比特流覆盖 10-100 MHz 全频段，运行时自动（或半自动）校准到最优采样点。

---

## 技术约束（Artix-7 / 7 系列）

### MMCM 能力
- VCO 范围：600-1440 MHz
- CLKIN 范围：10-800 MHz
- CLKOUT PHASE 分辨率：45°/DIVID（DIVID=10 时步长 4.5°）
- **DRP（Dynamic Reconfiguration Port）**：可运行时改写 MULT/DIVID/PHASE 寄存器（XAPP888）
- **PSINCDEC 接口**：可运行时以 ~1/56 × VCO周期 步进调整某个 CLKOUT 的相位（VCO=840MHz 时步长 ≈ 21.3ps）
- DRP 改写后需要 RST→等 LOCKED，延迟 ~100μs
- PSINCDEC 不需要 reset，一次步进 ~1 clock cycle 完成

### IDELAYE2 能力
- 31 taps × ~78ps/tap = ~2.4ns 总范围
- 对 84M（半比特 5.95ns）：2.4ns < 5.95ns → **能覆盖 eye center**
- 对 21M（半比特 23.8ns）：2.4ns 远不够 → **不能独立到 eye center**
- VAR_LOAD 模式：运行时改 tap（1 个 ref 200M 周期生效）

### OVERSAMPLE 能力
- 用 200MHz 参考时钟过采样（5ns 分辨率）
- 对 21M（半比特 23.8ns）：5ns 步长有 4-5 个有效采样点 → OK
- 对 84M（半比特 5.95ns）：5ns ≈ 1 个采样点 → **不够**
- 结论：OVERSAMPLE 只适合低速（<~25M）

## 方案对比

### 方案 A：MMCM DRP 全动态重配置

**原理**：运行时通过 DRP 端口改写 MMCM 的 CLKFBOUT_MULT、CLKOUT_DIVIDE、CLKOUT_PHASE 寄存器，然后 reset MMCM 等重新 lock。

**实现**：
1. 频率检测器：用系统 100MHz 时钟计 TRACECLK 边沿间隔 → 得到频率
2. 查表：频率 → 对应 MULT/DIVID（确保 VCO 在 600-1440M）
3. DRP FSM：按 XAPP888 序列写 MMCM 内部寄存器
4. 相位微调：PSINCDEC 步进扫描找最优相位

| 维度 | 评估 |
|------|------|
| 频率覆盖 | 10-100 MHz 全覆盖（任意 MULT/DIVID 组合） |
| 相位分辨率 | ~21ps（PSINCDEC @ VCO=840M） |
| 切换延迟 | ~100-500μs（reset + re-lock） |
| LUT 估算 | ~800-1200（频率检测 + DRP FSM + 查表 + PSINCDEC 控制） |
| 复杂度 | 高（DRP 寄存器映射复杂，需严格按 XAPP888） |
| 风险 | DRP 写错一个 bit MMCM 不 lock → 全系统挂；需充分仿真 |
| 参考 | Xilinx XAPP888, UG472 Chapter 3 |

### 方案 B：MMCM 固定 VCO + PSINCDEC 纯相位微调

**原理**：MMCM 的 MULT/DIVID 在综合时选一个能覆盖"最大目标频段"的值（如 MULT=10, DIVID=10 → VCO=TRACECLK×10），**不改频率参数**。只用 PSINCDEC 接口做运行时相位微调。

**关键限制**：VCO = TRACECLK × MULT。如果 MULT=10：
- 84M → VCO=840M ✓
- 42M → VCO=420M ✗（<600M，不 lock）
- 21M → VCO=210M ✗

**所以一套 MULT 只能覆盖一个频段**。要覆盖全频段仍需 DRP 改 MULT（回到方案 A）。

**但如果只需要覆盖 42-100MHz（产品实际用例）**：MULT=10 可以让 42M-100M 对应 VCO=420M-1000M（42M 差一点，45M 以上全覆盖）。实际上 MULT=12: 42M→504M(✗) 50M→600M(✓) ... 不够。MULT=15: 42M→630M(✓) 84M→1260M(✓) 96M→1440M(✓, VCO 上限)。

| MULT | 42M→VCO | 84M→VCO | 可覆盖范围 |
|:---:|:---:|:---:|:---:|
| 10 | 420(✗) | 840(✓) | 60-144M |
| 12 | 504(✗) | 1008(✓) | 50-120M |
| 15 | 630(✓) | 1260(✓) | **40-96M** |
| 16 | 672(✓) | 1344(✓) | 38-90M |

**MULT=15 覆盖 40-96 MHz**（VCO 600-1440M），包含 42M 和 84M！

| 维度 | 评估 |
|------|------|
| 频率覆盖 | 40-96 MHz（产品目标频段） |
| 相位分辨率 | VCO/56 步长 = 630M/56=11.25MHz → 周期 88.9ns → 步长=88.9/56=1.59ns... 不对。PSINCDEC 步长 = 1/(56×VCO_freq) 秒。VCO=630M→步长=28.4ps；VCO=1260M→步长=14.2ps |
| 切换延迟 | 0（PSINCDEC 不需 reset，每步 1 VCO cycle ≈ 1ns） |
| LUT 估算 | ~300-500（PSINCDEC 控制 + 频率检测 + 质量反馈） |
| 复杂度 | 低-中（无 DRP，只用 PSINCDEC 端口） |
| 风险 | 低（MMCM 参数固定，只调相位步进） |
| 限制 | <40M 和 >96M 需要不同比特流 |

### 方案 C：IDELAY 逐 lane 静态校准 + MMCM 纯频率跟踪

**原理**：MMCM 只做频率复制（0° 相位，纯提供 fabric 时钟），**数据采样延迟完全靠 IDELAYE2**。每条 lane 用 IDELAY 独立调 tap 对齐 eye center。

**问题**：IDELAY 总范围只有 ~2.4ns。对于 84M（半比特 5.95ns），eye center 在 ~3ns 处 → **超出 IDELAY 范围**（2.4ns < 3ns）。

**Workaround**：MMCM 出一个粗偏移（比如 45° 或 90°），IDELAY 做精细微调。但这又回到了"相位随频率变"的问题。

| 维度 | 评估 |
|------|------|
| 频率覆盖 | 仅 >~100MHz（IDELAY 够到 eye center）；低速不行 |
| 相位分辨率 | 78ps/tap |
| 切换延迟 | ~5ns（IDELAY reload） |
| LUT 估算 | ~300 + per-lane CSR |
| 复杂度 | 低 |
| 风险 | 中（>100M 才好用，和产品目标频段不完全匹配） |

### 方案 D：MMCM PSINCDEC + 上位机半自动扫描（推荐）

**原理**：方案 B 的工程化落地版本。MMCM 综合时用 **MULT=15, DIVID=15**（覆盖 40-96M）。CLKOUT1 的 PHASE 设一个中间值（如 90°）作为起始点。运行时：

1. FPGA 上电 → MMCM 以初始 90° 相位 lock
2. 上位机通过 UDP CSR 发"步进"命令 → FPGA 触发 PSINCDEC（单步 +/- ~20ps）
3. 每步后上位机抓一小段 trace → 测 unknown%
4. 扫完一圈（360° / 20ps 步长 ≈ 数百步）→ 找最低 unknown 的位置
5. 锁定最优相位 → 开始正式 trace

**或者全硬件版**：FPGA 内置一个简单 FSM，利用 traceIF 的 sync 检测（`REsyncPacket || FEsyncPacket`）作为质量指标——能连续检测到 TPIU sync 帧 = 相位正确。FSM 步进相位直到连续 N 帧 sync 成功 → 锁定。

| 维度 | 评估 |
|------|------|
| 频率覆盖 | 40-96 MHz（MULT=15）；加 DRP fallback 可扩展到 10-150M |
| 相位分辨率 | ~20ps（PSINCDEC @ VCO≈840M 均值） |
| 切换延迟 | ~1ns/步 × ~50 步（典型扫描）≈ 50ns 每次校准 |
| LUT 估算 | ~400-600（PSINCDEC FSM + sync 检测 + CSR） |
| 复杂度 | 中 |
| 风险 | 低（MMCM 参数综合时确定，运行时只微调相位） |
| 产品形态 | 上电自动校准 ~5ms 完成，无需 PC 干预 |

## 推荐方案：D（MMCM PSINCDEC + 自校准 FSM）

### 架构

```
                                    ┌─────────────────────┐
TRACECLK ─→ IBUF ─→ BUFG ─→ MMCM ─┤ CLKOUT0 (0°) = trace_clk (fabric)
                                    ├ CLKOUT1 (初始90°+PSINCDEC) = clk_sample
                                    ├ PSEN/PSINCDEC/PSDONE ←── phase_ctrl FSM
                                    └─────────────────────┘
                                           │
TRACED[3:0] ─→ IBUF ─→ IDDR(.C=clk_sample) ─→ trace_a/trace_b
                                                      │
                                               traceIF(.traceClkin=clk_sample)
                                                      │
                                              sync_detect (连续N帧sync?)
                                                      │
                                              phase_ctrl FSM:
                                                if (!locked):
                                                  PSINCDEC step++
                                                  if (sync_ok for N frames):
                                                    locked=1, stop
```

### 自校准 FSM 伪代码

```
state SCAN:
    for step in 0..MAX_STEPS:
        trigger PSINCDEC (+1 step)
        wait PSDONE
        count = 0
        for frame in 0..CHECK_FRAMES:
            if traceIF.sync_detected:
                count++
        if count >= THRESHOLD:
            goto LOCKED
    // 扫完没找到 → 报错（LED 常亮）

state LOCKED:
    // 正常工作
    if continuous_sync_loss > TIMEOUT:
        goto SCAN  // 温漂等导致失锁，重扫
```

### 参数选择

| 参数 | 值 | 理由 |
|------|-----|------|
| MULT | 15 | VCO=TRACECLK×15: 40M→600M(✓) 84M→1260M(✓) 96M→1440M(✓) |
| DIVID | 15 | CLKOUT freq = TRACECLK（1:1 跟随） |
| 初始 PHASE | 90° | 中间起始点，减少扫描步数 |
| PSINCDEC 步长 | VCO/56 周期 ≈ 14-28ps | 比 4.5° 分辨率精细 100 倍 |
| MAX_STEPS | 56×15=840（满圈） | 保证找到眼心 |
| CHECK_FRAMES | 8 | 快速判断（每帧 4-16 TRACECLK = 几十 ns） |
| THRESHOLD | 6/8 | 容忍偶发丢帧 |

### 预期校准时间

- 每步：PSDONE(1 VCO cycle) + 8 帧检测(~128 TRACECLK @84M = 1.5μs) ≈ 2μs
- 全圈扫描：840 步 × 2μs = **~1.7ms**
- 实际（eye 宽度 >30% → 找到就停）：~0.5ms

### 资源估算

| 模块 | LUT | FF | 备注 |
|------|-----|-----|------|
| 频率检测器 | 50 | 30 | 计数 TRACECLK 周期 |
| PSINCDEC 控制 | 80 | 40 | 步进 + PSDONE 同步 |
| sync 质量检测 | 100 | 60 | 连续帧计数 |
| FSM + CSR | 100 | 50 | 状态机 + UDP 状态读回 |
| **总计** | **~330** | **~180** | 远小于 35T 余量 |

## 与现状的兼容性

1. **不破坏现有 4-bit 84M 路径**：MULT=15, DIVID=15 时 VCO=84×15=1260M (✓)，CLKOUT1 频率=84M，和现在 MULT=10, DIVID=10 等价但 VCO 不同
2. **WIDTH 参数保持**：traceIF 路径（WIDTH=2）和 raw 路径（WIDTH=4）不受影响
3. **向后兼容**：上位机不发扫描命令时 FSM 可以自行完成校准（全硬件），或保持初始相位（降级到静态模式）
4. **21M 覆盖问题**：MULT=15 时 21M→VCO=315M < 600M（不 lock）。需要 MULT=30→VCO=630M 才行。但 MULT=30 时 84M→VCO=2520M（超 1440M）。**一套 MULT 无法同时覆盖 21M 和 84M**——需要 DRP 切换 MULT（方案 A 的 fallback），或放弃 21M 支持（产品目标是满速，21M 只用于调试降速）

## 实施路径

### Phase 1（最小可行）—— 1-2 天
- MMCM 改用 MULT=15, DIVID=15
- 加 PSINCDEC 端口暴露到 UDP CSR（上位机手动步进）
- 上位机 Python 脚本扫相位测 unknown → 输出最优步数
- 验证 42M 和 84M 都能校准到 <1% unknown

### Phase 2（自动化）—— 2-3 天
- 加硬件 sync 检测器（traceIF 的 `REsyncPacket || FEsyncPacket`）
- 加 phase_ctrl FSM（上电自动扫描到锁定）
- LED 指示校准状态（慢闪=扫描中，常亮=已锁定）
- 验证上电后自动校准 <2ms 完成

### Phase 3（DRP fallback）—— 3-5 天
- 加频率检测器 + MULT 查表
- 加 DRP FSM（XAPP888 序列）
- 覆盖 10-150 MHz 全频段
- 温漂重校准逻辑

## 对比上游 orbtrace

| 维度 | 上游 orbtrace (ECP5) | 我们方案 D |
|------|:---:|:---:|
| 采样时钟 | TRACECLK 直接（源同步） | MMCM CLKOUT1（相位可调） |
| 相位调整 | DELAYG 静态 tap（手动） | PSINCDEC ~20ps 步进（自动） |
| 频率适应 | 不需要（源同步天然适应） | MULT=15 覆盖 40-96M；DRP 扩展全频 |
| 校准方式 | PC 辅助扫 tap（planned） | 硬件 FSM 自动 + PC 可选介入 |
| 校准时间 | ~10s（PC 扫 32 tap × 网络往返） | ~1.7ms（全硬件本地） |
| 分辨率 | ~78ps/tap（IDELAY） | ~20ps/step（PSINCDEC） |

**我们的方案在分辨率和自动化程度上优于上游**，代价是需要 MMCM（ECP5 用 PLL 的 DPA 实现类似功能但更简陋）。

## 结论

**方案 D（PSINCDEC + 自校准 FSM）** 是最适合产品形态的选择：
- 一个比特流覆盖 40-96 MHz（包含 2-bit 满速 84M 的产品目标）
- 上电 <2ms 自动校准，无需 PC 干预
- ~330 LUT，对 35T 几乎无影响
- 分辨率 ~20ps，远优于当前 4.5° 步长
- 预期可将 unknown 从当前的 2-4% 压到 <0.5%（精确对准 eye center）
