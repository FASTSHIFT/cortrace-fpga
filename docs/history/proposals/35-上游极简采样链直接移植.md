# 提案 35 — 直接移植上游极简采样链（扔掉自造采集前端）

> 日期：2026-07-18
> 状态：**RETIRED（红方 r27 证伪）**。doc 16 的 CAP_RAW=0 帧路径已是本提案要移植的
>   上游结构（IDDR+同域 traceIF 组帧+128-bit 整帧跨域），实测三坑已消仍 99.7% 非法；
>   R7A/R7B 仿真坐实真凶是**采样漏/多边沿**（IDDR 在 edge-aligned 数据采在跳变点），
>   而这正是"换上游结构"碰不到的环节。真方向转采样相位/漏边沿（见 doc 16 末节 + r27）。
> 关联：proposal 22/26（采样方案）、proposal 33（per-lane IDELAY）、doc 16（2.5% 根因链）、
>       r26（占空比根因证伪）
> 触发：反复调试证明——2.5% CDC 撕裂、半 nibble 偏移、HSYNC 淹没，全部来自我们
>       **自造的采集前端**（`trace_capture_a7.v` 的 ref_200m/IDELAY/OVERSAMPLE/BUFR_IO +
>       自写 CDC）；而这些复杂度**上游 orbtrace 根本没有**。

## 1. 问题定义

移植至今，板载采集链是自造的 `trace_capture_a7.v`，包含上游没有的一大堆机制：
- `ref_200m` 独立采样域 + IDELAYCTRL/IDELAYE2 per-lane 延迟
- OVERSAMPLE 模式（边沿检测 + EYE_DELAY 计数）
- BUFR_IO 时钟方案
- **自写的 trace_clk→ref_200m 字节级 CDC**（裸总线 toggle）

调试史证明这些是 bug 温床：
- 裸总线 CDC → 2.5% 随机字节撕裂（doc 16，r26 R4 坐实）
- 字节级跨域 → 半 nibble 偏移（真 ETM has_tpiu_sync=False）
- CAP_RAW=1 抓裸字节 → HSYNC 淹没（data-ish 28%）

## 2. 上游 orbtrace 的采样链（实读源码 `trace/glue.py`）

```python
class TraceIO(Module):
    def __init__(self, pads):
        for i in range(4):
            self.specials += DDRInput(
                clk = traceclk,        # TRACECLK 本身当采样时钟
                i   = tracedata[i],
                o1  = self.trace_a[i], # 上升沿 nibble
                o2  = self.trace_b[i], # 下降沿 nibble
            )
        self.comb += ClockSignal().eq(traceclk)  # 整个 trace 域 = TRACECLK
```

上游 `trace/core.py`：
```python
traceif    = DomainRenamer('trace')(TraceIF())              # 在 TRACECLK 域组帧
trace_fifo = DomainRenamer({'write':'trace','read':'sync'})(
                AsyncFIFOBuffered(tpiu.TPIURawFrame, 4))     # 组完帧才跨域
... trace_fifo.output → tpiu_demux → ...
```

**上游极简结构（4 个关键事实）**：
1. **纯 IDDR 双沿采，采样时钟 = TRACECLK 本身**。无 IDELAY、无 ref 过采、无 OVERSAMPLE、
   无相位校准。
2. **采样 + 组帧全在 TRACECLK 域**（`ClockSignal().eq(traceclk)`），**这一段无 CDC**。
3. **只在组完 128-bit 帧后，用 AsyncFIFO 整帧原子跨域**到 sys 域。
4. edge-aligned 相位靠 ECP5 IDDRX1F 的**固有输入延迟**天然落眼内（testbench 注释
   "don't worry about phase"）。

## 3. 本提案：直接移植这个极简链到 Artix-7

新建 `trace_upstream_top.v`，忠实复刻上游数据流，最大化复用现成件：

```
trace_clk_in ─IBUF─BUFG─┬─────────────────► trace_clk (采样+组帧域)
                        │
trace_data_in ─IBUF─► IDDR(C=trace_clk) ──► trace_a[3:0]/trace_b[3:0]
   (×4, 无 IDELAY)                              │
                        traceIF.v (在 trace_clk 域) ──128-bit Frame──►
                          │  (复用 verilog/traceIF.v，已锁 sync/滤 HSYNC/组帧)
                          ▼
                        axis_async_fifo(128-bit, trace→sys, 格雷码原子传帧)
                          │  (复用，已 CI 验证；等价上游 AsyncFIFOBuffered)
                          ▼
                        sys 域：帧字节流 → fpga_core_net → UDP → host
                          │
                        host: 帧字节 as-is → OpenCSD（字节序已由 traceIF_tb 标定）
```

**相对 trace_capture_a7 扔掉的**：ref_200m 采样域、IDELAYCTRL/IDELAYE2、OVERSAMPLE
FSM、BUFR_IO、EYE_DELAY、自写字节级 CDC、duty 统计、SELFTEST 注入。

**复用的现成件**：
- `verilog/traceIF.v`（orbuculum 原版，组帧+sync）
- `axis_async_fifo`（verilog-ethernet，CI 已测，等价上游 AsyncFIFO）
- `fpga_core_net.v`（网络输出）
- host OpenCSD 链（`opencsd_etm4_run.py`）
- （单源 H743 无需 demux；如需多流再接导出的 `tpiu_demux.v`）

## 4. 关键差异：Artix-7 IDDR 无 ECP5 的固有延迟

上游能"不管相位"是因为 ECP5 IDDRX1F 有固有输入延迟把采样推入眼内。**Artix-7 的 IDDR
没有**——直接在 TRACECLK 边沿采 = 采在 edge-aligned 数据的跳变点（doc 14 §22）。

本提案的赌注：**先按上游最简结构（BUFG + 裸 IDDR，无 IDELAY）实测**，用已标定的
traceIF 帧路径 + 真 ETM 解码正确率做判据。若相位不够好（解码脏），**再按需最小补偿**：
- 选项 a：单个全局固定 IDELAY（把 4 lane 一起延迟约 1/4 UI 进眼内）——比 per-lane 简单
- 选项 b：加一个 90° 相移的采样时钟（MMCM，但会引入 gap 失锁问题，慎用）
不预先加 IDELAY/OVERSAMPLE，避免重新引入被证伪的复杂度。

## 5. 预期收益

- **一次性消除** doc 16 记录的三个坑（CDC 撕裂 / 半 nibble 偏移 / HSYNC 淹没），因为
  它们都来自自造前端，而上游结构里不存在这些环节。
- 采集链与上游 1:1 对齐，后续可直接接上游导出的 tpiu/orbflow Verilog 模块。
- 已部分验证：traceIF 帧路径已在硬件解出真实 func_test PC（37 个，doc 16）。

## 6. 风险与未决

| 风险 | 说明 | 缓解 |
|------|------|------|
| Artix IDDR 无固有延迟，裸采相位差 | edge-aligned 采在跳变点 | 先实测；不够再加单个固定 IDELAF/相移 |
| traceIF 需 TPIU sync 才组帧 | 真 ETM sync 稀疏时组帧少 | BB=1 提高锚点；或提高 TRACECLK sync 密度 |
| gap 容忍（停走时钟）| 采样+组帧在 TRACECLK 域，停则停，本就 gap 容忍 | AsyncFIFO 读空即停，无需额外处理 |
| 高频 TRACECLK 下 traceIF 时序收敛 | traceIF 组合逻辑在 TRACECLK 域 | 实测时序；必要时流水化 |
| 当前 37 PC / 99.7% 非法 | 帧路径质量差 | 本提案假设根因是自造前端；替换后复测 |

## 7. 实施步骤

1. 写 `trace_upstream_top.v`：IBUF+BUFG+IDDR(×5) → traceIF → axis_async_fifo(128b) →
   fpga_core_net。
2. 写 `run_trace_upstream.tcl`（复用 trace_stream 的源列表 + xdc）。
3. 编译、烧录，真 ETM（BB=1）抓，OpenCSD 解码，量**非法事件率**（vs 当前 99.7%）+
   func_test 覆盖 + 逐指令正确率。
4. 若相位差：加单个全局固定 IDELAY 扫一遍找眼心（这次 IDELAY 在组帧前、同域，不涉 CDC）。
5. 达标后接导出的上游 orbflow 模块，或保持网络直出。

## 8. 验收判据

- 真 ETM 解码**非法事件率显著低于当前 99.7%**（目标 < 5%），且 A-sync 后稳定跟
  Trace-Info。
- 与旧版 12M（781 PC）同频公平对照，覆盖率不劣化。
- 严格逐指令判据（非集合去重），连续正确指令段中位数显著提升。
