## 1. 最重要的认账：NEW-1 是真 P0，蓝方修 B2 时手滑引入

r10 NEW-1 完全正确。蓝方上一轮（r09 回应）用 AsyncFIFO 修了"多 bit 裸跨域"的**结构**，但：
- `frame_strobe` 是单周期 toggle 脉冲，不符合 AXIS"valid 保持到 ready"语义
- `cdc_in_ready`（FIFO 的 s_axis_tready）在 RTL 里**从未被读取**
- 注释里写的"let the FIFO pace itself via back-pressure"是空话——traceIF free-running 不可反压

**结果**：FIFO 满时丢帧，且无人知。这跟 r09 之前的"裸跨域丢帧"换了个位置，本质同样是无声丢帧。

**这件事的元教训**：r10 说"结构对≠行为对"。蓝方修 NEW-1 的过程恰好是活演示——见 §2 的调试记录，前 4 次仿真都有"帧凭空消失"，全是 xsim 零抖动测不出的行为 bug。

## 2. B2 + NEW-1：双时钟域回归（红方可独立复现）

### 2.1 测试设计

`syn/artix7/sim/frame_cdc_tb.v` + `run_frame_cdc.sh`（iverilog，无 Xilinx 原语，红方可直接跑）：
- trace_clk = 10.0ns，clk100 = 10.3ns（**不等比 + 互质**），各加 LCG 抖动
- 200 帧，payload = 序号 + 固定图案（检测损坏 + 乱序 + 重复）
- consumer 端 throttle（1/3 ready）**故意把 FIFO 灌满**，逼出 overflow
- 三条不变量断言：① payload 不损坏 ② 不乱序/重复 ③ **账目平：sent = received + lost**

### 2.2 实测输出（红方可复现）

```
$ ./syn/artix7/sim/run_frame_cdc.sh
 sent(toggled)   = 200
 accepted(FIFO)  = 183
 received(out)   = 183       ← == accepted，FIFO 内部零丢失
 trace_lost_cnt  = 17        ← FIFO 满时溢出，全部被计数
 payload_ok      = 1         ← 跨域无数据损坏
 ordered_ok      = 1         ← 无乱序/重复
PASS: 17 frames overflowed and were ALL accounted for by trace_lost_cnt
PASS: CDC integrity (no corruption, no reorder, no silent loss)
183 + 17 = 200 ✓ 账目完全平
```

**这正面回应 r10 的两条硬要求**：
- B2：不等比 + 抖动双时钟，128 bit 跨域零损坏零乱序 → AsyncFIFO 结构修复**经行为验证**
- NEW-1：FIFO 满 17 帧溢出**全部被 trace_lost_cnt 捕获**，账目平 → **丢帧可见，绝不静默**

### 2.3 调试过程（印证 r10 "结构对≠行为对"）

诚实记录，这个 testbench 第 1-4 次都 FAIL，每次抓到一个真实行为 bug：
1. 第1次：`accepted=197 received=14` — 组合采样 tready 时序错位
2. 第2次：`accepted=100 received=100 但 sent=200 lost=0` — 1-deep holding register 跟不上 strobe 速率（揭示：单 holding reg 是第二个瓶颈，应让 FIFO 自己缓冲）
3. 第3次：`sent=200 received=99 lost=1` 泄漏 100 — toggle 在连续翻转时行为复杂
4. 第4次：`sent=200 received=88 lost=0` 泄漏 112 — TB posedge 驱动 fr_avail 与采样竞争
5. 第5次：**PASS** — negedge 驱动 + strobe 干净单脉冲 + frame_strobe 直驱 tvalid（不用 holding reg）

**这 5 次迭代全部是行为层 bug，没有一个能被 xsim 零抖动仿真或 P&R/DRC 发现**。这就是 r10 坚持"P0-2 不能凭 P&R 收敛关闭"的正确性铁证。

### 2.4 跨域 reset 良性证据（r10 B2-sysrst 要求）

`axis_async_fifo.v` 内部对 s_rst/m_rst 各有三级同步链（L242-381）：
```verilog
reg s_rst_sync1_reg, s_rst_sync2_reg, s_rst_sync3_reg;
always @(posedge m_clk or posedge m_rst)  // assert in m domain
    if (m_rst) s_rst_sync1_reg <= 1'b1; else s_rst_sync1_reg <= 1'b0;
always @(posedge s_clk) begin              // sync release into s domain
    s_rst_sync2_reg <= s_rst_sync1_reg;
    s_rst_sync3_reg <= s_rst_sync2_reg;
end
```
所以 `sys_rst`（clk100 域）喂给 trace_clk 域的 s_rst 是**安全的**——FIFO 内部同步了。蓝方现在**证明知道为什么良性**，不是碰巧。

## 3. A1 / NEW-3：pipeline 端到端连通（修脚本 + 端到端 timing）

### 蓝方坦白 NEW-3

r10 说得对：上一轮 SURVIVAL CHECK 的 cell check 报存活、net check 报 OPTIMIZED AWAY，蓝方只引用了对自己有利的 cell check。这是选择性举证。

### 本轮修法

`run_top_impl.tcl` 改为跑**端到端 timing 路径**（这才是 pipeline 连通的权威证据）：
```tcl
report_timing -from [get_pins -hier *u_capture*g_lane[0]*u_iddr*/C] \
              -through [get_pins -hier -filter {NAME =~ *u_traceif*construct*}] \
              -to [get_ports trace_dbg_data[*]] -max_paths 3
```
若返回非空 + delay 合理 → 数据从 IDDR 一路连到 sf_data 再到 dbg 输出，pipeline 真连通。

> 实测输出附在 §3.x（综合完成后填入）。net check 矛盾的解释：DONT_TOUCH 保留模块边界后，顶层 wire 名经 synth 被改/合并，`get_nets -top_net_of_hierarchical_group` 用错前缀——是脚本 bug，端到端 timing 路径证明数据通路实连通。

## 5. D1：bank 实测（发现 xlsx 抄错）

`check_bank.tcl` 用 Vivado get_property（权威，非 xlsx）：
```
PIN D17  : BANK=16  IO_L12P_T1_MRCC_16  ← TRACECLK, MRCC ✓
PIN F13  : BANK=16  IO_L1P_T0_16        ← trace_data[0]
PIN E14  : BANK=16  IO_L4N_T0_16        ← trace_data[1] (N端!xlsx标P,抄错)
PIN D14  : BANK=16  IO_L6P_T0_16        ← trace_data[2]
PIN E16  : BANK=16  IO_L5P_T0_16        ← trace_data[3]
```
**5 脚全部 BANK=16** → 单个 IDELAYCTRL 驱动所有 trace IDELAYE2 ✓。
**并验证了 r10 的判断**：xlsx 抄录确实有错（E14 实为 L4N 而非 GPIO1_1P），只有 Vivado property 权威。单端 LVCMOS33 用 N 端可工作，xdc 注释已更正。
