# 红方评审 V2（第二轮）：M核指令流 Trace · Zynq 方案

> 评审对象：`M核指令流trace-Zynq方案-V2-蓝方回应.md`
> 立场：红方。本轮**不重复 C1–C4/S1–S5**，只审 V2 的修正是否"改对了"，并专攻本轮新增的 §8bis（资源/算力评估）。
> 警惕原则：**承认问题 ≠ 解决问题。** 重点抓"嘴上认了、方案没真改""为补旧漏洞引入新乐观"。

---

## 总评判

**V2 在'诚实度'上大幅进步，但在'可投入性'上仍不达标——它把 V1 的乐观从'工作量'转移到了 §8bis 的'资源/算力'与 PoC 判据上，且新引入了一个动摇选型根基的战略矛盾（PS 仅搬运 ⇒ 为何还要 Zynq）。结论：可解锁 PoC，但 §8bis 的三组数字全是无实测支撑的估算，PoC 判据缺量化阈值，当前不能据 V2 批准主体投入。**

一句话：**V2 认错认得漂亮，但 §8bis 是"用新的乐观数字填上旧的乐观措辞"，且推荐变体自我拆台。**

## 一、V2 仍未解决 / 解决不彻底（逐条）

### U1〔能力档位 A 与"无损/无插桩"初衷自相矛盾——档位 A 本身就是一种插桩〕

- **V2 怎么说**：§1.2 档位 A = "杜邦线 + trace_clk ≤25MHz + **被测 CPU 降频或轻负载**"，称其"完整、无丢包"，适用"可重现的 UAF（降频复现）"。
- **问题仍在哪**：方案目标白纸黑字是"**性能无损、无插桩**"。**降被测 CPU 主频/负载，本身就是对被测系统时序的扰动**——它和插桩一样会移动、掩盖、制造 Heisenbug。蓝方在 §1.3 自己承认"竞态型 UAF……降速会改变时序、可能掩盖 bug"。于是档位 A 能无损抓的，恰好是**最不需要 trace 工具就能查的逻辑型 bug**；而真正值得动用指令流 trace 的高价值目标（竞态、时序相关 UAF、性能问题）**全部落在档位 A 之外**。把"能做的子集"（低速逻辑 bug）包装成"方案可用"，而真正的需求场景只能靠档位 B。
- **量化逼问**：请给出——你们要定位的 UAF 样本里，**能在降频下复现的比例**是多少？若 <50%，则档位 A 对核心用途（UAF 定位）**不构成可交付能力**，方案的真实可用模式只有档位 B（转接板满速）。
- **档位**：致命（打击方案的目标自洽性，是 C1 的延伸而非重复——C1 攻"数字不可兼得"，U1 攻"V2 给出的化解手段 A 与初衷冲突"）。

### U2〔档位 B 的"短转接板"被一笔带过——它正是被 Zynq 声称"消掉"的那个硬件未知〕

- **V2 怎么说**：§1.2/§7.1 把转接板描述为"比复刻整个 ORBTrace 简单，但仍是一项 PCB 工作，必须计入成本"。
- **问题仍在哪**：转接板要做 **50Ω 阻抗控制 + 等长（<12.5mm 偏差）+ MIPI-20 座 + 端接**——这是一块**需要设计、打样、用示波器/眼图调 SI 的受控阻抗 PCB**。而方案 §0 的立项根基是"Zynq **消掉硬件不可靠这个未知变量**"。**真正的硬件难点从来不是 FPGA 数字板（买现成确实消掉了），而是 trace 端口的信号完整性**——而这个最硬的 SI 未知，V2 又通过"必做转接板"原样请了回来。
- **自相矛盾**：蓝方以"自制 ORBTrace 要打板调硬件"为由否定它，自己却引入一块**必做、且 SI 敏感**的转接板。两者都要打板、都要调 SI；差别只是转接板无源、更简单——但"无源更简单"不等于"没有硬件未知"，受控阻抗 + 眼图调试恰恰是 SI 未知本身。
- **档位**：致命（动摇 §0 立项理由：Zynq 并未消掉真正的硬件未知，只是把它从"FPGA 板"挪到"转接板"）。

### U3〔PoC-B 是"命门门禁"却没有客观通过/失败判据——没有阈值的门禁等于没有门禁〕

- **V2 怎么说**：§3/§9 V-2 = "源同步采样时序报告 + ILA 眼图/抽头扫描"，达标线"setup/hold 正余量，TRACECLK 落 MRCC"。
- **问题仍在哪**："正余量"是定性词。**多少 ps 算过？眼图开度占 UI 多少算过？IDELAY 抽头有效窗口要几个 tap？BER 要在多长采集、什么温度/电压下不超过多少？** 没有这些，PoC-B 就是"做了 ILA 看一眼，看着像对"——这正是红方第一轮要根除的"无量化门禁"。蓝方把 PoC-B 前移为门禁（结构对了），但门禁的**判据是空的**（没改对）。
- **档位**：严重（门禁形同虚设，见下方"PoC 判据要求"给出红方要求的硬阈值）。

### U4〔V-1…V-10 存在依赖闭环，PoC-B 满速档无法在 PoC 期内真正完成〕

- **V2 怎么说**：§9 把 V-2（采样）、V-5（TCP 吞吐）、V-7（量产/转接板形态）并列为"主体投入前必测"，且 §3 说 PoC-B 满速档"必须在短转接板上做"。
- **问题仍在哪**：构成依赖闭环——
  - PoC-B **满速档** 依赖 **转接板**（V-7 的产物）；
  - 转接板设计依赖 **目标 trace_clk**（V-1 的产物）与 **选板 bank/落点**（V-4）；
  - 而 V-7（量产形态）又被 §7 列为"遗留待办"。
  - ⇒ **PoC-B 满速档实际上要求先完成一次受控阻抗 PCB 的设计-打样-调试**（2–6 周 + 打样周期），它**塞不进"PoC-B 2–3 周"的盒子**。PoC-B 在杜邦线上只能证明"低速档采样链路正确"，**证明不了满速可行性**——而满速可行性才是整个方案对核心用途（竞态 UAF）的命门。
- **结论**：当前 PoC-B 的**范围被低估**：它被拆成"低速链路验证（杜邦线，2–3 周，可做）"与"满速验证（需转接板，含打样，数周起，未列入 PoC 预算）"两件事，而后者才是真门禁。V2 没区分这两者。
- **档位**：致命（命门 PoC 的范围与排期不实，等于门禁可被"低速通过"蒙混，而满速风险照样后移）。

### U5〔S2/500MHz 出口带宽：V2 自己把它降为"逼近上限、无富余、需调优"，却仍保留 7020 选型理由〕

- **V2 怎么说**：§5 修正为 500MHz≈800Mbit/s，GEM 优化后 ~900、未优化/双向 ≤500；"逼近上限，不是余量充足"。
- **问题仍在哪**：这等于承认——**选 7020 的唯一理由（为 500MHz 留余量）在出口带宽上并不成立**：GbE 在 500MHz 满速下没有余量，且需要零拷贝 + 内核调优才"逼近"达标。那么 7020 相对 7010 的额外 LUT/BRAM，在出口被 GEM 卡死时**变不成可用的满速吞吐**。
- **档位**：严重（选型理由被自己的修正掏空，详见战略矛盾 N3）。

## 二、V2 新引入的问题（为回应旧质疑而产生的新乐观/矛盾）

### N1〔§8bis 用"门数不是约束"暗度陈仓为"工作量小"——资源富余 ≠ 开发省力〕

- §8bis.6 反复强调"逻辑门完全不是约束、7010 都富余 4–5 倍"。这是对的，但**与工作量无关**：HDL 的难度在**时序收敛、跨时钟域、校准状态机的正确性与验证**，不在 LUT 占用率。§2.2 自己写着 PL ~20–34 人日。**"资源够"被放在显眼位置，容易诱导读者把'塞得下'读成'好做'。** 这是 V1"零研发"乐观的**变形回归**：从"工作量小"退到"资源富余"，但叙事重心仍在弱化难度。
- **档位**：次要（措辞诱导，非硬错误，但需要纠偏）。

### N2〔推荐架构在一篇文档内三次横跳，蓝方未定分工〕

- §2.2 注："**PS 软件解析变体列为推荐**"。
- §8（标题）："**PL 最小化 + PS 软件解析**作为降风险首选"。
- §8bis.4："**最稳的工程选择**：PS 不做解析、只搬运，解析全交给 PC。"
- §8bis.5 表：A/B/C 三方案并列。
- ⇒ **同一份 V2 里"推荐/首选/最稳"指向了不同的三个方案（B：PS软件解析 → C：PS仅搬运PC解析）**。这说明蓝方**自己没定 PL/PS/PC 的分工边界**。分工未定，则 §2.2 的"20–34 人日"、§8bis 的资源/算力估算**全部失去基准**（不同分工下 PL/PS 负载完全不同）。
- **档位**：严重（无确定架构 ⇒ 所有工作量/资源数字无锚点）。

### N3〔战略级新矛盾：PS 仅搬运 ⇒ Zynq 相对"小FPGA+USB"丧失不可替代性〕

这是 V2 最致命的自拆台，由 §8bis.4 的"最稳选择"直接引出：

- 若 PS **只做 DMA 搬运 + 网络转发、不解析**，则：
  1. PL 仍需做完整采样前端 + 帧组装（甚至全流水线）——**与小 FPGA 方案的 HDL 工作量等同**；
  2. PS 额外背上 **PetaLinux + AXI-DMA 驱动 + ring buffer + TCP 应用**——这是 ORBTrace 的 **ECP5 + 简单 USB2 FIFO 桥** 完全不需要的复杂度。
- **那么 Zynq 相对 ORBTrace 原架构（ECP5/小FPGA + USB2 直吐 PC）的不可替代优势只剩两条**：GbE（>USB2 的 480Mbit/s）与 DDR3 大缓冲。但是——
  - **当前目标 F4/F7（252–324Mbit/s）：USB2 的 480Mbit/s 已经够**，GbE 优势用不上；DDR3 大缓冲在"PS 仅搬运"下也并非瓶颈（见 R3，真正的瓶颈是 PL 侧小 FIFO，与 Zynq 无关）。
  - ⇒ **对当前 F4/F7 目标，"PS 仅搬运的 Zynq"是"小FPGA+USB"的劣化版**：同等 HDL 工作量 + 多一套 PetaLinux/DMA 税，换来用不上的 GbE。
  - Zynq 只有在 **500MHz 满速 + PL 硬件解析（用上 PS/HP 高带宽通路与 DDR3）** 时才真正不可替代——而那个场景 §5 已承认 GEM 出口没余量、§8bis.4 已承认要退回 PL 硬件解析（20–34 人日那条）。
- **结论**：V2 推荐的"低风险变体"（PS 搬运/PC 解析）**恰恰抽掉了选 Zynq 的理由**。要么承认"当前 F4/F7 阶段其实该用 ORBTrace/小FPGA+USB，Zynq 是为 500MHz 未来下注"，要么承认 Zynq 的价值绑定在尚未验证的 500MHz+PL硬件解析路径上。**两种诚实说法 V2 都没给，反而把'最省事'的搬运变体当推荐，等于一边选 Zynq 一边废掉 Zynq。**
- **档位**：致命（动摇选型根基，且是 V2 为降 PL 工作量而新引入的）。

## 三、资源 / 算力评估（§8bis）专项质疑

### R1〔LUT "~2-4K"：类比估算，且关键三块被系统性低估，DMA 通路一项就可能吃光整个预算〕

- **无实测支撑**：§8bis.2 自注"**待 PoC 综合后用真实 utilization 报告替换**"——即**承认现在这个数字是猜的**。把"猜的数字"做成带小计的表格，形式上像分析，实质是 V1 乐观的换皮。
- **独立反算（指出低估处）**：
  - **AXI-DMA 通路**：V2 给"AXI-Stream + AXI-DMA ~500–1000 LUT"。但 Xilinx AXI DMA LogiCORE 在 **Scatter-Gather 模式** 本体就约 **1.5–4K LUT**，再加到达 PS HP 口所需的 **AXI SmartConnect/Interconnect（~1–2K LUT）** 与 DataMover。**仅 DMA 通路就可能 3–5K LUT，单独超过 V2 给整条通路的"2–4K"总数。**
  - **5 路 deskew 校准状态机**：被 §8bis.2 归进"~几百 LUT 胶水"。但**逐 lane IDELAY 抽头扫描 + 眼心搜索 + 训练图案检测 + IDELAYCTRL 管理**是一个真实的 deskew 控制器，量级 **500–1500 LUT**，不是"几百胶水"。
  - **Amaranth→Verilog 重写膨胀**：tpiu/cobs 原是 Amaranth 推断的紧凑实现，人工重写为 Verilog 后**面积通常持平或膨胀**，不会更省。
- **修正后的现实区间**：采样前端+校准 1–2K、流水线（traceIF+TPIU+COBS+OrbFlow+CDC）1.5–2.5K、DMA 通路 3–5K ⇒ **≈6–10K LUT**，是 V2"2–4K"的 **2–3 倍**。
- **结论分级**：**"LUT 不是约束"这个定性结论对 7020（53.2K）仍成立**（用 ~12–19%），对 7010（17.6K）则从"用 1/5"恶化到"用 35–55%、余量收紧"。**所以 R1 不是致命——致命的是把猜测数字包装成可信分析。** 真实结论应是："7020 够用且有余量；7010 偏紧；精确数字 PoC 综合前不可知。"
- **档位**：严重（数字不可信、且 7010 余量被夸大；但"塞得下 7020"的方向成立）。

### R2〔A9 "5–15 cycle/byte"：无 benchmark，且对 trace 解析这种强分支强数据依赖负载严重乐观；"双核分流"忽略串行依赖〕

- **无实测支撑**：§8bis.4 自注"**待 PoC-V6 实测替换**"，来源写"通用 ARM Cortex-A9 标量处理估算"——即**拍脑袋**。
- **为何 5–15 cyc/byte 乐观**：trace 解析不是顺序 memcpy，而是——
  - `Unmangle`：逐字节 half-byte 位重排、ID 位提取；
  - `TrackStream`：通道状态机（每字节判 is_id、更新 channel）；
  - `COBS GroupSplitter`：逐字节分支 + 254 计数 + 分组边界数据依赖；
  - 数据从 **DDR3 流入（非 cache 常驻）**，是 cache-cold 流式负载，每次 L2 miss 几十 cycle。
  - 综合强分支（分支误预测）+ cache-cold load + 位操作，A9（双发射但流水深）现实更可能是 **15–40 cyc/byte**，5 是 memcpy 级的幻想值。
- **独立反算（即便用蓝方乐观值）**：500MHz 目标 ~100MB/s × 8 cyc/byte = **800 Mcyc/s**。
  - 7010 @ 667MHz：800/667 = **120% 单核 → 单核根本不够**（V2 只说"吃力"，实为"溢出"）。
  - 7020 @ 866MHz：800/866 = **92% 单核 → 几乎占满，没有给中断/调度/网络栈留任何余量**。
  - 若用现实的 20 cyc/byte：100MB/s×20 = 2000 Mcyc/s = **866MHz 双核的 115%——双核也不够。**
- **"双核分流"忽略串行依赖**：TPIU 去混淆 / COBS 是**逐字节、帧边界数据依赖**的串行状态机，**无法按数据并行切分**（不解码就找不到帧边界）。只能**流水线式**拆（核0 做 TPIU demux、核1 做 COBS），但需跨核队列 + cache 一致性流量，**加速比现实约 1.3–1.6×，不是 2×**，且被最慢级卡住。V2 把"双核"当作 2× 的免费午餐。
- **档位**：致命（§8 软件解析变体的命门数字不可信且大概率乐观 2–4 倍；直接决定 B/C 变体在 500MHz 是否成立）。

### R3〔BRAM/DMA：把主缓冲推到 DDR3 是"类别错误"——DDR3 在 DMA 的下游，无法缓冲 DMA 自身的失速〕

这是 §8bis 最严重的逻辑漏洞，属"认错但没改对"。

- **V2 怎么说**：§8bis.3 "主缓冲不放 BRAM、放 PS 的 DDR3（数百 MB，秒级抗突发），PL 只留几 KB~几十 KB 小缓冲……**彻底解开 ORBTrace 那轮 BRAM vs HyperRAM 的死结**。"
- **问题仍在哪（独立反算）**：
  - 抗突发/抗失速所需的缓冲，**必须位于数据通路上"会失速的那一环"的上游**。会失速的环是 **AXI-DMA + DDR 仲裁 + Linux 中断/调度**。
  - **DDR3 恰恰在 AXI-DMA 的下游**——数据要先**经过 DMA 才能进 DDR3**。**DDR3 无法缓冲 DMA 自身的服务间隙**，因为缓冲的对象（DMA 失速）发生在到达 DDR3 之前。
  - 真正吸收 DMA 服务延迟的，**只有 PL 侧那块"几 KB~几十 KB"BRAM FIFO**。它的深度才是抗突发能力的上限，**与 DDR3 有多大毫无关系**。
  - **反算**：档位 B 满速净 50MB/s、峰值 100MB/s。32KB PL FIFO @ 100MB/s = **320µs** 抗失速窗口。而 Linux 下中断驱动的 SG-DMA 在 A9+GEM+DMA 三方争 DDR 时，**描述符回收 + 调度抖动的最坏间隙可达数十 µs ~ ms 级**——一次 1ms 的调度停顿就冲掉 32KB FIFO。
  - 对照 ORBTrace：8MB HyperRAM @ 50MB/s = **160ms** 容限，比 Zynq 的 PL FIFO 高 **三个数量级**。所以**"BRAM vs HyperRAM 差 100 倍"的死结非但没解开，反而更糟**——Zynq 真正能用来抗 DMA 失速的是 KB 级 PL FIFO，比 ORBTrace 的 8MB 还小。
  - 可缓解但 V2 没说：用 **cyclic/proxy DMA + 大描述符环**让 DMA 不依赖 CPU 逐次干预，则瓶颈降为 DDR 争用延迟（µs 级），几十 KB FIFO 或可够。**但这要求指定 DMA 模式并实测最坏服务间隙，V2 用"几 KB 足矣"一笔带过，零测量。**
- **结论**：§8bis.3 的"DDR3 秒级抗突发解开死结"是**把 DDR3 容量误当作抗失速缓冲**的类别错误。绑定约束仍是 PL FIFO 深度 vs 最坏 DMA 服务间隙，**必须实测，不能假设**。
- **档位**：致命（声称"解开死结"实为逻辑错误，旧风险换形式仍在）。

## 四、对 PoC 判据的要求（每个 PoC 必须补的客观通过/失败阈值）

无量化阈值的 PoC 不予承认。红方要求：

**PoC-A（目标侧吐 trace）**
- 通过：在 trace_clk = X MHz 下，示波器实测 TRACED0-3 相对 TRACECLK 的 **建立/保持窗口 ≥ 1.0 ns**；连续采集 ≥ 10 s 无电平异常。
- 必交付：**(CPU 主频 / 负载) → (不触发 ETM overflow 的最高 trace_clk 与对应平均 trace 率)** 实测对照表；并标注 UAF 目标样本中**可在降频复现的比例**（回应 U1）。

**PoC-B（源同步采样，命门，须拆两档）**
- **B-低速（杜邦线，可在 2–3 周内做）**：trace_clk ≤ 25MHz；IDELAY 抽头扫描给出**有效窗口 ≥ 8 taps**（@78ps ≈ 0.62 ns 余量）；连续采集 ≥ 10 min，**误帧率（sync 丢失/坏帧）< 1e-9**。仅证明低速链路。
- **B-满速（必须在受控阻抗转接板上，含打样，单列排期，非 2–3 周）**：trace_clk = 目标值（50–100MHz）；ILA/示波器眼图**水平张开 ≥ 0.5 UI、垂直 ≥ 200 mV**；setup/hold **正余量 ≥ 0.3 ns**（报告须含 -40/+85℃ 或至少室温 + 电压 ±5% 角点）；BER < 1e-12 over ≥ 1 min。
- **失败即止损**：B-满速不达标 ⇒ 竞态型 UAF 不可定位 ⇒ 方案对核心用途不成立。
- **必须明示**：B-满速依赖转接板，**不得用 B-低速通过冒充 PoC-B 通过**（回应 U4）。

**PoC-C（上位机链路）**
- 通过：用**已知正确的 OrbFlow 样本**喂 Orbuculum，解出的指令流与参考 golden 逐字节一致；记录确切命令行与版本。

**PoC-资源/算力（§8bis 三项，本轮新增要求）**
- **V-9 LUT/BRAM**：必须给**选定分工方案（A 或 B 或 C，先定下来）**下的 **Vivado 综合+实现后 utilization 报告**，而非估算表；落在器件内且 LUT 余量 ≥ 30%。
- **V-6 A9 算力**：必须给**实测 cycle/byte**（在 DDR3 流式、cache-cold、开中断/网络栈的真实条件下跑 orbuculum C 解析），而非"5–15 估算"；并给出**单核/双核实测吞吐**与目标 trace 率的比值。
- **V-10 缓冲/DMA**：必须实测 **PL FIFO 在最坏 DMA 服务间隙（含 Linux 调度抖动、GEM/A9 争 DDR）下的溢出阈值**；明确 DMA 模式（是否 cyclic、描述符环深度）；给出"PL FIFO 深度 vs 最坏失速窗口"的余量，而非"几 KB 足矣"。

## 五、红方最终立场

**V2 够格解锁 PoC 投入（结构对了：PoC 前移、能力分档、工作量据实），但不够格据 V2 批准主体投入——因为 §8bis 三组数字全是自认的估算，PoC 判据无阈值，且推荐变体（PS 搬运）抽掉了选 Zynq 的理由。**

**解锁 PoC 的前置条件（必须同时满足）：**

1. **先定分工**（消除 N2）：在 A（PL 全硬件）/ B（PS 软件）/ C（PS 搬运 PC 解析）中**锁定一个主方案**，否则所有资源/算力数字无锚点。红方建议：**当前 F4/F7 目标若选 C，必须先回答 N3——为什么不直接用 ORBTrace/小FPGA+USB？** 选 Zynq 的理由必须绑定到 500MHz+PL硬件解析（方案 A）并接受其全部工作量。
2. **PoC-B 拆成 B-低速 / B-满速两个门**，且**承认 B-满速含一次受控阻抗转接板打样、单列排期与成本**（消除 U4）。B-满速是真命门。
3. **每个 PoC 附第四节的量化阈值**，无阈值的 PoC 结果不予承认（消除 U3）。
4. **U1 量化交付**：UAF 样本可降频复现比例。若主要目标是竞态型，则直接进入"必须 B-满速 + 转接板"路径，不要用档位 A 制造"已可用"的假象。

**缺口总结（按致命度）：**
- 致命：U1（档位 A 与无损初衷冲突）、U2（转接板=未消掉的 SI 未知）、U4（PoC-B 满速范围/排期不实）、N3（PS 搬运废掉 Zynq 选型理由）、R2（A9 算力乐观 2–4 倍）、R3（DDR3 缓冲类别错误）。
- 严重：U3（PoC-B 无判据）、U5（500MHz 出口无余量却保留选型）、N2（分工未定）、R1（LUT 数字不可信、7010 余量夸大）。
- 次要：N1（"资源富余"诱导"工作量小"）。

**一句话批示**：**先把"到底为什么是 Zynq、到底主推哪个分工、转接板算不算硬件未知"这三件事说清楚，再带着第四节的量化阈值去跑 PoC-B。在此之前，V2 是一份诚实的'问题清单'，不是一份可投入的'实施方案'。**
