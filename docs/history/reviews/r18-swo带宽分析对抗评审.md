# r18 · F429-SWO-bandwidth-analysis 对抗性评审

> 评审对象：`docs/artix7-port/proposals/16-swo带宽榨取分析.md`
> 立场：红方，严格证伪。已读：上游 `swo.py`（PulseLengthCapture `In(2)`）、`crg_ecp5.py`（swo2x=250MHz）、`trace_capture_a7.v`、doc15/r17 实测（NRZ 单沿 200MSa/s 干净到 21M、28M 开始碎）。
> **前置立场（决定权重）**：SWO 的唯一战略意义是**省线束**（真实产品对线缆极苛刻，5 线并口在产品上不现实）。所以评审不否定"做 SWO"，而是审"追平/超越 ORBTrace 带宽"这个**目标本身值不值得、账算得对不对**。

---

## 总裁决

**该改 + 降级目标，IDDR 双沿前端可以做，但"追平/超越 ORBTrace 48Mbps"是个错误的北极星。**

- **省线束这个理由成立且重要**——这才是 SWO 该做的真正原因，但**这份分析通篇没提它**，反而把目标设成"追平/超越 ORBTrace 带宽"。**目标设错了**：省线束只需要 SWO **够用**（能在产品可接受的线束下解出指令流），不需要它**最快**。
- **采样率账是"理论采样率"不是"实测可达吞吐"**：从 200MSa/s(21M) 线性外推到 500MSa/s(62M) 忽略了 r17/doc15 自己的实测信号——21M 已经是 6 字节 I-sync 在 28M 开始碎的边缘，**这条曲线已经在弯，不是线性**。
- **GPIO Fmax ~90M 当 SWO 墙是纸面值**：datasheet Fmax 是规定负载下的翻转极限，不是"NRZ 眼图在长杜邦线 + 我们这套重启就崩的 SI 下还开着"。并口刚因排线崩到 15%，凭什么 SWO 在 56–90M 下杜邦线眼图还在。
- **最尖锐的矛盾**：分析把 SWO 推到 56M 仍是 **stall 节流 trace**（分析 §3 自己承认"SWO 始终是瓶颈、stall 始终限速"），而项目存在理由是**并口满速实时**、真命门（并口重启崩 15%）**还没解**。**在一个能赢但不重要的战场上加码。**

## 逐条质疑

### Q1 采样率账：200→500MSa/s 线性外推（21→62M）成立吗？

【结论：**证伪（线性外推无依据，且与自己的实测矛盾）**】

**依据**：
1. **算术起点大致对**：`crg_ecp5.py` 确认 swo2x=250MHz，`PulseLengthCapture.input` 是 `In(2)`（每周期吃 2 个采样）→ ORBTrace 等效 500MSa/s 这个数**成立**。我们单沿 200MSa/s 是其 1/2.5 也对。**到此为止账是对的。**
2. **但 21M→62M 的外推违背自己的实测曲线**。doc15/r17 自己写：单沿 200MSa/s **干净到 21M、28M 开始碎**。也就是说在 200MSa/s 下，**21M（≈9.5 采样/bit）干净、28M（≈7 采样/bit）就碎**。碎点不是采样率线性外推能消的，它来自：
   - **脉宽量化误差随 symbol 变短被放大**：脉宽测量的绝对误差是 ±1 采样周期。21M 时 1 bit≈9.5 采样，±1 是 ±10%；62M @500MSa/s 时 1 bit≈8 采样，±1 是 ±12.5%——**采样率提了 2.5×，但每 bit 采样数几乎没变（9.5→8）**，因为 baud 也提了 2.5×。**量化裕度不增反降。** 这是分析最大的算术错误：它把"等效采样率"当成"可达 baud"，**但脉宽测量的真实指标是"每 symbol 采样数"，而那个数在两者间几乎相同（~8–9）**——所以 ORBTrace 的 62M 和我们 21M 的"每 bit 采样数"是同档的，**我们的瓶颈不是 2.5× 采样率差，21M 本就接近脉宽测量在 ~8 采样/bit 的固有上限**。提 IDDR 到 500MSa/s **不会**让 62M 像 21M 那样干净，因为 62M@500MSa/s 的每 bit 采样数 ≈ 21M@200MSa/s，**会碎在同样的相对裕度处**。
   - 同步链亚稳态、IDELAY 抖动、edge/centre 对齐——这些是固定时间误差（r15/r16 反复出现），symbol 越短占比越大（r16 频率相关性已实证：5.25M 更频繁、10.5M 几乎全坏）。**r16 的频率相关曲线就是这条非线性墙的直接证据，分析没引用自己刚验过的它。**

**最低成本实验**：**不写 IDDR，先纯软件证伪**。把现有 200MSa/s 实测抓取的脉宽流，**人为下采样模拟"更高 baud / 更少采样每 bit"**（或反过来，用现有 28M 那次"开始碎"的数据），画出 "每 bit 采样数 vs unknown%" 曲线。若 unknown 在 ~8 采样/bit 急升——**证明 62M@500MSa/s（≈8 采样/bit）会和 28M@200MSa/s 一样碎，线性外推证伪**。成本：0 RTL，1 个分析脚本。

### Q2 IDDR 双沿用于 SWO 是否等价于 ORBTrace 脉宽测量 / 是否混淆两种 IDDR 用法

【结论：**存疑——技术上可行，但分析混淆了"源同步 IDDR"和"过采样 IDDR"，且"原语现成、改动小"是贴金**】

**依据**：
1. **两种 IDDR 是根本不同的用法**：
   - **ORBTrace SWO（过采样 IDDR）**：用**自由跑的 swo2x（250MHz）**当采样时钟，DDR 双沿采**异步单线 SWO**，得 2 采样/周期。没有时钟线、不需要相位对齐、IDELAY 不用于对眼（SWO 无固定相位可对）。
   - **我们 `trace_capture_a7` 的 IDDR（源同步）**：用 **TRACECLK 当采样时钟**采**源同步并口数据**，IDELAYE2 用于 per-lane 对眼。
   - **这是两套完全不同的配置。** 分析说"已有原语 IDDR + IDELAYE2，改动小"——**误导**。我们现有的是源同步配置，SWO 要的是过采样配置，**IDELAY 在 SWO 上根本不对眼（无相位可对），等于从头搭一个不同用途的 IDDR 例化**，不是"复用现有"。
2. **7 系 IDDR 双沿对采样时钟占空比敏感**：用 IDDR 在固定时钟双沿采，要求**采样时钟占空比严格 50%**，否则两个半周期采样间隔不均 → 脉宽测量误差。MMCM 出的 250/400MHz 占空比一般 OK，但这是个新约束，分析没提。
3. **技术本身可行**：过采样 IDDR 采异步单线、喂 PulseLengthCapture，是 ORBTrace 验证过的正路，**方向对**。只是不是"改现有源同步 IDDR"那么轻。

**最低成本实验**：仿真 `swo_pulse_capture` 用 IDDR 模型（2 采样/周期）喂上游 `test_swo.py` 向量，确认脉宽流与上游一致。成本：复用现有向量 + xil_stubs 的 IDDR 模型，0.5 天。**但先做 Q1 的软件证伪——如果 62M 注定碎，IDDR 都不用搭。**

### Q3 GPIO Fmax 当 SWO 上限是否过于乐观

【结论：**证伪（纸面值，实际被 SI 拉低一个量级）**】

**依据**：
1. datasheet 的 Fmax（10/30/50pF→100/90/50MHz）是 **ST 在规定负载、单根线、理想测试条件下的翻转极限**——它保证的是"引脚能翻这么快"，**不保证"NRZ 数字眼图在你的杜邦线 + 共地 + 重启会崩的 SI 下还能被对端干净采样"**。
2. **自证据反驳**：分析自己引用"并口刚因重启动排线崩到 15%"（r16）。**同一套杜邦线 + 共地接法**，凭什么 SWO 在 56M（symbol 18ns）、84M（symbol 12ns）下眼图还开着？50pF 长杜邦线的 RC + 反射在几十 MHz 就让边沿塌成斜坡。**90M 这个墙是引脚能力的墙，不是链路眼图的墙**，实际可用 baud 大概率被 SI 拉低到 datasheet 值的 **1/2~1/10**。
3. **真实产品线束更苛刻**：评审前置——产品上线缆受限。产品级线束（细、长、可能带连接器）的 SI 比实验室杜邦线**更差**，56–90M 在产品线束上几乎不可能。**省线束的代价恰恰是 baud 被线束 SI 压低**——这与"追求高 baud"直接冲突。

**最低成本实验**：用 LA（金标准）抓 PB3 在 ACPR=2（56M）、ACPR=1（84M）下的波形，看眼图是否还开。**0 FPGA RTL**，直接 LA。若 56M 眼图已塌 → GPIO Fmax 墙证伪，实际墙是 SI。

### Q4 ACPR 整数分频点的现实性（56M 下 stall/full-sync/重锁还撑得住吗）

【结论：**存疑，且分析只论证了"能采到字节"未论证"能解出指令流"**】

**依据**：
1. **baud 越高 stall 越狠 → full-sync 越稀**。r17/doc15 已记录：21M 时"TPIU full-sync 几乎不发（stall 拖慢 CPU）"。56M 时 SWO 排空更快、CPU 跑更快、瞬时 ETM 码率更高 → 相对 SWO 带宽的过载比 **更严重**，full-sync/I-sync 锚点**更稀**。而我们的解码（etm35lib）**依赖 I-sync 锚点重锁**——锚点越稀，一次 baud 失锁/坏字节后**重新对齐的间隔越长，丢失的指令流越多**。
2. **"能采到字节" ≠ "能解出指令流"**：分析全程论证的是采样率/baud（前者）。但高 baud 下 NRZ 异步失锁（bitlen 错配）会**静默出错字节**，喂进解码 → 散落错（和并口"散落 nibble 错"同病）。**分析没有任何一处论证"56M 下解出的 PC 命中率"**，只论证了"采样率够 56M"。
3. **定频约束放大**：NRZ 异步要求 CPU 定频，56M 下若有任何调频（中断/低功耗）立即失锁——比 21M 更不容错。

**最低成本实验**：若真要验，STM32 配 ACPR=2(56M) + LA 抓 PB3 → 喂 etm35lib，看**I-sync 锚点数 + unknown%**，和 21M 比。**不是看"抓到多少字节"，是看"解出多少真 PC"**。成本：复用支线 LA 流程，改 ACPR。

### Q5 ISERDES 的 >100M 是不是画饼

【结论：**对 F429 是画饼（分析自己承认用不满），且复杂度被低估**】

**依据**：
1. **分析自己写**：F429 GPIO Fmax ~90M 用不满 ISERDES 的 >100M，要换 H7/H5。**那 ISERDES 对当前 F429 项目就是纯理论**，写进"超越 ORBTrace"是用一个**当前硬件够不着**的能力撑结论。
2. **"注释里写了 ISERDES 适合 >500Mbps 单线"被当成"我们能轻松用上"的证据**——这是贴金。ISERDES 1:8 解串**异步无时钟单线**的真实复杂度：bitslip 对齐、字边界恢复、ISERDES→fabric 的 CDC、过采样下的位投票——这些 ORBTrace 用 IDDR+PulseLengthCapture 恰恰**绕开了**（脉宽测量不需要 bitslip）。**用 ISERDES 反而比 ORBTrace 的方案更复杂**，分析把"原语存在"当成"能力可得"。
3. SWO 是脉宽编码的异步线，**ISERDES 的固定相位解串本来就不是 SWO 的自然匹配**（SWO 没有固定 bit 边界相位）；要用 ISERDES 还得在它后面再做脉宽测量，**等于 ISERDES 只当了个更快的过采样器**——那不如直接 MMCM 提采样时钟 + 单沿/IDDR，简单得多。

**最低成本实验**：无需实验，逻辑上即可判定——**当前 F429 项目删掉 ISERDES 这条**，它不贡献任何可达价值。

### Q6 战略：追平/超越 ORBTrace 带宽是否偏离主线

【结论：**证伪（在能赢但不重要的战场加码）**】

**依据**：
1. **项目存在理由 = 并口满速实时**。SWO 无论 21M 还是 56M 都是 **stall 节流**（分析 §3 自己承认"无论多高 baud 都是以 stall 拖慢 CPU 换不丢包"）。**节流 trace 改变被测程序时序**，不是"满速实时"。把 SWO 从 21M 推到 56M，**仍然是节流的**，只是 CPU 被拖慢程度从 1/20 变 1/7——**对"满速实时"这个目标，21M 和 56M 没有本质区别，都不是它**。
2. **真命门没解**：并口重启崩 15%（r16）——这是决定整个 FPGA 方案成败的命门，**还没钉死**。把工时投到"SWO 追平 ORBTrace"，是绕开命门。
3. **SWO 的正确目标是"省线束 + 够用"，不是"最快"**。省线束只要求：在**产品可接受的线束**下，SWO 能**够用地**解出指令流。给定 Q3（产品线束 SI 更差 → baud 被压低），**正确的 SWO 目标 baud 应该是"产品线束上眼图还开的最高 baud"，很可能就在 10–20M，而不是 56M**。追 56M/62M 对省线束这个真目的毫无帮助，反而因高 baud 对线束 SI 更敏感而**有害**。

**最低成本实验**：回答一个问题即可——"把 SWO 从 21M 推到 56M，对'省线束让产品能用 trace'这个目标，多解决了什么？" 若答不出（因为 21M 已能解出指令流、且 56M 在产品线束上更难），战略证伪。

## 总评：执行 / 改 / 搁置

**判定：目标该改，IDDR 双沿前端可低优先级做，"追平/超越带宽"该搁置。**

1. **改北极星**：SWO 的目标从"追平/超越 ORBTrace 48Mbps"改成"**在产品可接受线束下，够用地解出指令流**"。省线束才是 SWO 的意义，而省线束与高 baud **方向相反**（线束越省、SI 越差、可用 baud 越低）。
2. **IDDR 双沿可以做，但理由是"比单沿多一倍裕度、让 21M 更稳/小幅上探到 ~30–40M"，不是"冲 62M"**。且要先做 Q1 的零成本软件证伪，确认每 bit 采样数下降到哪会碎。
3. **ISERDES 这条对 F429 删掉**——纯理论，不贡献可达价值。
4. **优先级低于并口 SI 命门**——并口重启崩 15% 没解之前，不该把工时投到 SWO 带宽竞赛。

## 点破自我说服处（直接说）

1. **把"理论采样率"当成"实测可达吞吐"**：全文核心论证是"采样率 200→500→1000 MSa/s ⇒ baud 21→62→100M"。但 r17/doc15 自己的实测（21M 干净、28M 碎）说明**真实指标是每 symbol 采样数，不是绝对采样率**——而 ORBTrace 62M 和我们 21M 的每 bit 采样数同档(~8)，**说明我们没有 2.5× 的提升空间，21M 已接近这套脉宽测量法的固有上限**。这是把采样率账当吞吐账的根本错误。
2. **用 ORBTrace 的成功给未验证路径贴金**：反复"ORBTrace 用 IDDR 500MSa/s 跑到 62M ⇒ 我们 A7 更强 ⇒ 也能 62M 甚至 >100M"。但 ① ORBTrace 的 62M 是它**自己的板 + 受控走线 + 可能更短链路**实测的，不是我们杜邦线；② "A7 比 ECP5 强"指的是 fabric/原语，**不改变 F429 输出端 SI 和脉宽测量的固有裕度**。借 ORBTrace 的数字背书我们杜邦线上的 62M，是跨硬件贴金。
3. **GPIO Fmax 90M 当成"我们能到 90M 量级"**：datasheet Fmax 是引脚翻转能力，分析把它当成链路可用 baud，**忽略了自己刚记录的"并口同款杜邦线重启就崩 15%"**——同样的 SI 会把 SWO 实际可用 baud 拉低一个量级。
4. **回避了战略层的不一致**：分析花大篇幅论证"能追平/超越带宽"，却没问"这对项目有什么用"——而它 §3 自己写明"SWO 始终 stall 限速"，等于自己承认了 SWO 再快也不是项目要的满速实时。**赢了一个对项目无意义的指标。**

> 一句话：采样率账的算术起点对（ORBTrace 500MSa/s 成立），但从那里外推到"我们能 62M 干净"用错了指标——真正决定 SWO 能跑多快的是"每 symbol 采样数"和"产品线束的眼图"，前者我们和 ORBTrace 同档（说明没 2.5× 空间）、后者比实验室杜邦线更差。SWO 值得做，但理由是**省线束**不是**追带宽**；这两个目标方向相反。先把并口那个崩 15% 的真命门钉死，再回来给 SWO 设一个诚实的、由产品线束 SI 决定的 baud 目标。
