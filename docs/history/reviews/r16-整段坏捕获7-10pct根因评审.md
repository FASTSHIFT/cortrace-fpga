# r16 · 间歇性整段坏捕获 (~7–10%) 根因评审（红队施压）

> 评审对象：`trace_capture_a7.v`（OVERSAMPLE + LOCKOUT + seen_rise）、`trace_stream_top.v`（CSR/gen/re-arm/SELFTEST）、`decode/{yield_test,selftest_check,traceclk_quality,onset_profile}.py`、`15-frequency-sweep-plan.md §9–11`、`14 §28`
> 立场：红队。蓝方已把问题从测量假象里救出来（这轮的进步是真的），但卡在最后 7–10%。**逐条施压，不接受"SELFTEST 干净 ⇒ 采集逻辑无罪"。**
> 已独立读：OVERSAMPLE 核心（含 `os_clk_src/os_data_src` 注入点、LOCKOUT、seen_rise/b_latched/cap_valid 全路径）。

## 总裁决（先给结论）

**蓝方的 SELFTEST 把"采集逻辑无罪"证过头了。** 读 RTL 确认 SELFTEST 的注入点是：
```verilog
wire       os_clk_src  = test_en ? test_clk  : trace_clk_ibuf;
wire [3:0] os_data_src = test_en ? test_data : data_dly;   // ← 注意：注入在 IDELAY 之后
```
SELFTEST 用 FPGA 内部 `test_clk`/`test_data` 替换了**同步器之前**的源，确实跑全了 ref 域的"3-FF 同步→边沿检测→LOCKOUT→EYE 计时→配对→cap_valid"逻辑。**但它系统性地不覆盖真实信号比内部方波多出来的恰好三件事**，而这三件正是 7–10% 的嫌疑池：

1. **IDELAY**：SELFTEST 注入 `test_data`，**绕过了 `data_dly`（IDELAYE2 输出）**——真实数据每条 lane 都过 IDELAY tap=16，SELFTEST 一点都没过。
2. **lane 间 skew**：`test_data` 是 FPGA 内部同时翻转的 ramp，**四条 lane 零 skew**；真实 ETM 四条 lane 有独立 PCB+IDELAY skew。
3. **真实时钟在 FPGA 引脚处的占空比/边沿**：SELFTEST 是 50% 占空的干净方波；真实 TRACECLK **在 FPGA 输入脚**的占空比/边沿质量**从未被测量**（LA 测的是 LA 探头点，不是 FPGA 脚）。

**最强单一线索是频率相关性**（1.31MHz ~7–10% / 5.25MHz 更频繁 / 10.5MHz 几乎全坏）。这个标度**排除了 r15 那种"概率/拍频"型纯亚稳态**（那应频率无关），**指向一个固定时间量的误差预算（duty 失真 / lane skew / 同步器抖动）随眼图收缩而占比变大**。下面论证：**最可能的单一根因是"真实 TRACECLK 在 FPGA 脚处的占空比失真"**（叠加双同步链延迟差），其次是 re-arm 竞态（解释双峰）。

## 一、"SELFTEST 干净 ⇒ 采集逻辑无罪 ⇒ 是物理/信号" —— 推理有真漏洞

### 蓝方主张
SELFTEST（内部干净异步方波回环）12 万 nibble 误码 0.002% ⇒ 采集逻辑无罪 ⇒ 病根在物理/信号。

### 红方拆解：SELFTEST 没覆盖的真实特性，恰好就是嫌疑池

| 真实信号有、SELFTEST 没有 | RTL 证据 | 为什么可能正是 7–10% |
|---|---|---|
| **过 IDELAYE2** | `os_data_src = test_en ? test_data : data_dly`——SELFTEST 用 test_data，真实用 data_dly(=IDELAY 输出) | IDELAY tap=16 给每条 lane ~1.25ns 延迟；若 IDELAYCTRL 在某些 re-arm 时刻未完全稳定，或 tap 校准漂移，real 路径有、SELFTEST 没有 |
| **lane 间 skew** | test_data 四 lane 同步翻转；真实 lane 各自 PCB+IDELAY 走线 | 在"edge+EYE_DELAY"单一采样点采全部 4 lane，若某 lane skew 使其数据在该点仍在过渡 → 散落 nibble 错 |
| **真实时钟占空比/边沿（在 FPGA 脚）** | SELFTEST test_clk 是 50% 干净方波 | duty≠50% 会让 rising/falling 两个半位不等宽，短的那个半位采样点偏出眼 → 散落错，**且频率越高占比越大** |
| **真实 IBUF 阈值/输入级** | SELFTEST 在 IBUF 之后注入（os_clk_src=trace_clk_ibuf 那支才过 IBUF；test_clk 不过） | FPGA IBUF 的 VIH/VIL 阈值 + 杜邦线反射可能使**过零点偏移→等效 duty 失真** |

**核心逻辑谬误**：SELFTEST 证明的命题是"**对一个 50%占空、零skew、不过IDELAY 的干净异步源，ref 域 FSM 正确**"。蓝方把它推广成"**采集逻辑对真实信号也正确**"——这是**以偏概全**。真实信号多出的 IDELAY/skew/duty 三个变量，SELFTEST 一个都没测，而它们正是采样架构（单点采样 + 双同步链）最敏感的输入。

### 裁决
🔴 **致命推理漏洞**。SELFTEST 干净**不能**推出"采集逻辑无罪"，只能推出"FSM 对良性源无罪"。"是物理/信号"这个结论方向**可能对**（见频率相关性），但蓝方是用一个证不到那里的实验推出来的，且把"物理/信号"和"采集架构对真实信号特性的敏感"混为一谈——**这两者要靠下面的实验分开**。

## 二、频率相关性 —— 最强线索，蓝方没充分利用

### 现象
1.31MHz ~7–10% 偶发；5.25MHz 更频繁；10.5MHz 几乎全坏。

### 红方分析：这个标度本身就是判据
- **若根因是 r15 式纯异步采样孔/亚稳态**：每个 bit 跳变落进采样孔的概率 ≈（setup+hold 窗）/（ref 周期），**与 TRACECLK 频率无关**。10.5MHz 不该"几乎全坏"。→ **频率相关性证伪了"纯亚稳态"是主因**（这点蓝方可以反过来用，是好消息）。
- **若根因是固定时间量误差**（duty 失真 δt、lane skew δt、同步器抖动 ±1 ref=±5ns、EYE_DELAY 固定 20ns）：误差占半位比例 = δt / (半位)。半位 @1.31MHz=380ns、@5.25MHz=95ns、@10.5MHz=47ns。**同一个 δt，占比从 5% 暴涨到 ~40%+**——**完美匹配"1.3M 轻微→10.5M 几乎全坏"的标度**。

**结论**：频率相关性强烈指向**固定时间量的 margin 侵蚀**，候选是 {duty 失真、lane skew、双同步链延迟差、EYE_DELAY 固定值}。其中 **EYE_DELAY=20ns 固定**这点要单独点名（见三）。

### 裁决
🟠 蓝方有这个数据却没拿它做根因判别。它**几乎独立地**把根因从"概率型亚稳态"逼到"固定时间 margin 型"——这是免费的、强有力的判据，蓝方应据此重排嫌疑。

## 三、RTL 审查：固定时间量误差的具体来源

### 来源 A：EYE_DELAY 是**固定 ref 周期数**，不随半位缩放
```verilog
wire [7:0] eye_use = (eye_delay_rt != 0) ? eye_delay_rt : EYE_DELAY;
// 采样点 = 检测到边沿后 eye_use 个 ref 周期
```
EYE_DELAY=4 → 固定 20ns。@1.31MHz 半位 380ns，20ns 是 5% 进入（深在眼内）；@10.5MHz 半位 47ns，20ns 是 **43% 进入**——还在眼内但已接近后沿，**叠加边沿检测的 ±5ns 抖动 + duty 失真**就会冲出。**EYE_DELAY 应按半位比例设（如半位/2），而非固定拍数**——蓝方扫了 EYE 值但都是固定拍，没做"按频率自适应"。这部分解释频率相关，但不是双峰。

### 来源 B：双同步链延迟差（r15 已指出，仍在）
时钟走 `tck_sync[2:0]`（3-FF，用 [2]^[1] 检测），数据走 `d_s0/d_s1`（2-FF）。**级数不同**，且各自 ±1 ref 抖动。"边沿时刻"与"被采数据"之间有 (3−2)=1 级系统偏移 + 抖动。SELFTEST 同样走这两条链却干净——**因为 SELFTEST 的数据在采样点附近不变化**（方波 ramp 半位内恒定）；真实信号若 duty 失真/skew 使数据在采样点附近仍在变，这条链差就放大成错误。**这条单独不致命，但是 duty/skew 的放大器。**

### 来源 C：seen_rise 只保第一个字节的配对，不保整段
```verilog
if (r_arm && r_cnt == 0) seen_rise <= 1'b1;
if (b_latched && seen_rise) begin cap_byte_r <= {b_reg, a_reg}; ...
```
seen_rise 确保第一个 emit 的字节是 (rising, falling) 正确配对。**但它是一次性门**——如果整段中途因 LOCKOUT 误吞/漏一个真实边沿（高频时 76 拍间距缩短，LOCKOUT=4 拍占比变大，且 raw_rise/raw_fall 在 duty 失真下可能贴近），配对会从该点起永久错半位。加 LOCKOUT 后现象从"中途突变"变成"从 byte0 均匀脏"——**说明错误不再是中途单次错位，而是从一开始就均匀散落**，这更像 duty/skew 的每周期小概率采错，不是配对错位。

### 裁决
🟠 来源 A（EYE 固定值）+ B（双链差）共同构成频率相关的 margin 侵蚀；C 已被 LOCKOUT 大幅缓解。**真凶更可能在 RTL 之外的输入特性（duty/skew/IDELAY），RTL 这几条是放大器。**

## 四、"均匀 14%" 像什么？—— 蓝方还没做的逐 bit/lane 统计

蓝方报告"原始 nibble 层面结构均匀、坏在去帧层、少量散落 nibble 错"，但**没做坏捕获的逐 bit / 逐 lane / 逐 nibble-value 统计**。这是**当前最该补、成本最低**的定性手段。"均匀 14%"可能是下面任一，而它们指向完全不同的根因：

| 统计特征 | 指向的根因 |
|---|---|
| 错误**随机散布在 4 条 lane**、随机 bit | 采样孔/亚稳态（但频率相关性已弱化此项）|
| 错误**集中在某 1 条 lane** | 该 lane 的 PCB/IDELAY skew 超眼 |
| 错误**集中在 b_reg（falling nibble）或 a_reg（rising nibble）** | **duty 失真**（一个半位窄→那个 nibble 偏出眼）——**最该先看的** |
| 错误偏好**特定 nibble 值/特定跳变方向**（如只在 0→1 或 1→0） | 边沿不对称 / 反射 / IBUF 阈值偏移 |
| 错误**成对/突发** | 配对错位 / cap_valid 双发漏发 |

**怎么做**（用已有 ground truth）：同会话 LA + FPGA 抓同一段（见六的 E0），把 FPGA 坏捕获与 LA 真值**逐 nibble 对齐 diff**，对每个错按 (lane index, a/b 即 rising/falling, nibble 值, 跳变方向) 分类直方图。`onset_profile.py`/`selftest_check.py` 已有解析骨架，扩一个 diff 分类即可。

### 裁决
🔴 这是**判别根因的关键一步，蓝方跳过了**。在拿到这个直方图前，"均匀 14%"是个未定性的黑盒，任何根因结论都是猜。

## 五、双峰（0% vs 14%）—— 必须有一个 per-capture 常量，re-arm 竞态是头号嫌疑

### 红方分析
双峰 = 每个捕获**要么全好要么全坏**，意味着存在一个**在 re-arm 时刻被锁定、并持续整个捕获的二值状态**。

**注意一个被排除项的反推**：两个自由跑的时钟（TRACECLK vs ref_200m）的相位在一个 6KB（~4.5ms @1.3MHz）捕获内会**扫过多个完整 beat 周期**——所以**任何"相位 beat"型根因都预测"每捕获有好有坏段"（连续分布），与双峰矛盾**。蓝方已经放弃 beat，是对的；但这也意味着**频率相关的 margin 侵蚀（duty/skew）如果是连续作用，应给出"每捕获都均匀脏"而非"双峰"**——**所以 duty/skew 解释了"脏的时候为什么脏 + 为什么频率相关"，但解释不了"为什么有的捕获完全 0%"**。

**能同时解释双峰 + 均匀的，是一个 per-capture 锁定的对齐/相位状态**：
- **re-arm 竞态**：软 re-arm（CSR 复位写指针 + 重新 arm）异步于 TRACECLK 与 ref 流水线。re-arm 释放的那一刻，`r_arm/f_arm/seen_rise/lock_cnt/d_s0/d_s1` 与进来的 TRACECLK 相位关系被**锁定为一个 per-capture 初值**。某些初值 → EYE 采样点整段落在安全相位 → 0%；另一些初值 → 整段系统性偏 → 均匀脏。**这能同时给出双峰 + 均匀 + 频率相关（偏多少相对眼图占比随频率涨）+ 只在真实信号（SELFTEST 的源相位与 ref 关系固定，每次 re-arm 落同一好相位 → 永远 0%）。**

**这条最关键的解释力**：为什么 SELFTEST 永远干净？因为 `test_clk` 是 FPGA 内部、与 ref_200m **同源/固定相位**，每次 re-arm 都落进同一个（好）相位桶；真实 TRACECLK 与 ref 异步，re-arm 落进哪个相位桶是随机的 → 双峰。**这一条把"SELFTEST 干净"从"采集逻辑无罪"重新解释成"SELFTEST 恰好永远命中好相位"——直接削弱蓝方的核心推理。**

### 裁决
🔴 **re-arm 竞态是双峰的头号嫌疑**，且它顺带给"SELFTEST 为何永远干净"一个不同于蓝方的解释。必须用"自由跑/不 re-arm"实验排除（见六 E1）。

## 六、能一次性区分根因的最小板上实验（用已有 ground truth，不跨会话猜）

按"先排竞态、再分物理特性"排序：

### E0（前置，必做）：同会话 LA+FPGA 逐 nibble diff 分类
LA 与 FPGA **同一次运行、同时**抓同一段（LA 50MSa/s 抓引脚，FPGA CAP_RAW 抓 cap_byte），用 TRACECLK 边沿序列对齐，对每个 nibble 错按 **(lane, a/b, 值, 跳变方向)** 直方图。**这一张图直接区分**：lane-skew（某 lane 偏）/ duty（偏 b_reg 或 a_reg）/ 亚稳态（均匀随机）/ 配对（成对突发）。**成本最低、信息量最大，先做。**

### E1：杀掉 re-arm 变量（区分"re-arm 竞态" vs "信号特性"）
改成**自由连续捕获**（不软 re-arm，连续滚动写 BRAM / 连续 dump），或把 re-arm 同步到一个**已知 TRACECLK 边沿**后再释放。
- **若双峰消失、坏率趋于单一稳定值** → **re-arm 竞态**坐实（per-capture 锁定状态是病根）→ 修 re-arm 同步握手。
- **若仍双峰** → 不是 re-arm，转 E2/E3。

### E2：物理回环 SELFTEST —— 让内部干净源走真实 I/O 路径（区分"FPGA I/O 路径" vs "STM32 信号"）
把 `test_data`/`test_clk` 从 FPGA **输出脚**驱动，用短线**回环接到 trace 输入脚**，从而经过真实 IBUF + IDELAY + 引脚 + 杜邦线，但源仍是 FPGA 已知干净方波。
- **若回环也出 7–10%/频率相关** → 病根在 **FPGA 侧 I/O 路径（IBUF 阈值/IDELAY/反射/duty）**，与 STM32 无关。
- **若回环干净、只有接 STM32 才坏** → 病根在 **STM32 侧信号特性**（TPIU 输出 duty/skew/边沿）。
- 这一步直接补上当前 SELFTEST 三个盲区里的"过 IDELAY + 过真实引脚"两个。

### E3：FPGA 自测真实 TRACECLK 占空比（不靠 LA，直接在 FPGA 脚测）
加一个 ref_200m 计数器，**测每个 TRACECLK 周期 tck_s 高/低的 ref 拍数**，做直方图。**这测的是 FPGA 输入脚处的真实占空比**（不是 LA 探头点）。
- **若 duty 明显≠50%（如 55/45 或随频率恶化）** → **duty 失真坐实**（来源 A/三的放大被点燃）→ 解法：rising/falling 用**独立 EYE_DELAY**（按各自半位宽设），或改回源同步 IDDR + IDELAY 移眼心。
- 这正面攻击"占空比在 FPGA 端 ≠ LA 探头端"这个未验证前提。

### E4：lane-skew 注入扫描（区分 skew）
SELFTEST 增强：给四条 `test_data` lane 加**可编程独立延迟**（各自过 IDELAY 不同 tap），扫 skew，看多大 skew 开始复现 14%。
- 若小 skew（几 ns）就复现 → lane-skew 是真凶之一 → 需 per-lane deskew 训练（Stage-3 本来要做的）。

**实验最小集与顺序**：**E0（定性错误分布）→ E1（排 re-arm 竞态）→ E2（FPGA I/O vs STM32）**。这三个跑完，根因基本锁定在 {re-arm 竞态 / FPGA I/O 路径(含duty) / STM32 信号} 之一；E3/E4 用于在"信号特性"内进一步定 duty vs skew。

## 七、未验证前提 / 谬误清单（分级）

**致命**
- F1：`SELFTEST 干净 ⇒ 采集逻辑无罪`——SELFTEST 绕过 IDELAY（注入 test_data 非 data_dly）、零 lane skew、50% 干净方波、且 test_clk 与 ref 固定相位（每次 re-arm 命中同一好相位）。它证的是"FSM 对良性源 + 固定相位无罪"，不是"对真实信号无罪"。
- F2：双峰 + 均匀 + 频率相关 + 仅真实信号 → 最可能是 **re-arm 竞态锁定 per-capture 相位状态**（头号），叠加 **真实 TRACECLK 在 FPGA 脚的 duty 失真 / lane skew**（决定脏的程度与频率标度）。蓝方未做 E0/E1，根因仍是猜。

**严重**
- S1：频率相关性已**证伪"纯亚稳态/拍频"为主因**，蓝方没用这条免费判据反推到"固定时间 margin 型"。
- S2："LA 边沿干净、duty 50.0%"测于 LA 探头点，**未验证 FPGA 输入脚**的 duty/边沿——这是"占空比两端不同"未验证前提。
- S3：EYE_DELAY 是固定 ref 拍数，不随半位缩放；高频时占比逼近后沿，与频率相关现象一致，蓝方扫了 EYE 但都是固定拍、未做按频率自适应。
- S4：双同步链级数差（3-FF clk / 2-FF data）持续存在，是 duty/skew 的放大器（r15 已提，未改）。

**次要**
- m1：LOCKOUT=4 固定拍，高频时占半位比例变大，可能在 10.5MHz 误吞真实边沿（边沿间距缩短）——高频"几乎全坏"的次要贡献。
- m2：seen_rise 仅保第一字节配对，对整段均匀错无作用（已被 E0 的分布区分覆盖）。

## 八、特别回答蓝方三问

**Q：最可能的单一根因？**
按解释力排序：**(1) re-arm 与真实信号的相位竞态**（唯一能同时解释双峰 + 均匀 + 仅真实信号 + SELFTEST 永远干净的机制）；**(2) 真实 TRACECLK 在 FPGA 输入脚的 duty 失真**（解释脏的程度 + 频率标度，且"FPGA 脚 ≠ LA 探头"未验证）；**(3) lane skew**。IDELAY 不稳是次要候选。**不是**经典 SI 眼图闭合（380ns 巨眼），**不是**纯亚稳态（频率相关性证伪）。

**Q：SELFTEST 推理的漏洞？**
见 F1。最致命的一点：SELFTEST 的 test_clk 与 ref_200m **同源固定相位**，每次 re-arm 落同一相位桶 → 永远干净；这恰好**掩盖了 re-arm 相位竞态**——SELFTEST 干净不是因为逻辑无罪，可能是因为它永远命中好相位。

**Q："均匀 14%" 像什么？**
未做 E0 前不能定。候选：偏 a/b（duty）、偏某 lane（skew）、均匀随机（亚稳态，已被频率相关弱化）、成对（配对）。**E0 一张逐 nibble 分类直方图即可定性。**

---

## 九、一句话结论

**蓝方这轮把问题从测量假象里救出来是真功劳，但最后 7–10% 卡住，是因为 SELFTEST 这个"无罪证据"证过了头：它注入在 IDELAY 之后、四 lane 零 skew、用 50% 干净方波、且 test_clk 与 ref_200m 同源固定相位——所以它只证明了"ref 域 FSM 对良性源 + 命中好相位时正确"，而真实信号多出的 IDELAY、lane skew、FPGA 输入脚处的真实占空比/边沿，以及 re-arm 落进随机相位桶，它一个都没测。最强线索是频率相关性（10.5MHz 几乎全坏），它独立地证伪了"纯亚稳态/拍频"，把根因逼向"固定时间量 margin 随眼图收缩而侵蚀"；而双峰（要么 0% 要么均匀 14%）要求一个 per-capture 锁定的常量，最可能是 re-arm 与真实 TRACECLK 的相位竞态——这同时解释了"SELFTEST 为何永远干净"（同源相位永远命中好桶）。先做三个实验定锤：E0 同会话 LA+FPGA 逐 nibble 按 (lane/a-b/值) 分类直方图（定性错误长相），E1 改自由连续捕获看双峰是否消失（排 re-arm 竞态），E2 把 FPGA 干净源经真实引脚+IDELAY 回环（分 FPGA I/O 路径 vs STM32 信号）。在 E0/E1 出来之前，"是物理/信号"仍是未证结论——很可能其实是 re-arm 竞态 + FPGA 脚 duty 失真的组合，而非 STM32 信号本身脏。**
