# r15 · OVERSAMPLE 采集 8% 误码根因评审（红队施压）

> 评审对象：`trace_capture_a7.v`（OVERSAMPLE）、`sim/xil_stubs.v` + `sim/tb_dsl_replay.v`、`trace_stream.xdc`、`14-logic-analyzer-ground-truth.md`
> 立场：红方 FPGA 源同步 + CDC 红队。**假设蓝方每条"已排除"都可能错，逐条施压。**
> 已独立读：上述全部 RTL/TB/XDC 实文件。

---

## 总裁决（先给结论，后逐条）

**蓝方进死胡同的根本原因：把一个"结构上不可能复现板上问题"的 sim 当成了"RTL 正确"的证据，于是反复在 SI / 相位 / EYE 上打地鼠，却从没质疑采样架构本身。**

读完 RTL，**8% 误码的最可能根因不是 SI、不是相位拍频，而是 (a) 采样架构缺陷——具体是两个叠加的硬伤**：

1. **`d_s0 <= data_dly` 在 ref_200m 域直接采异步数据**，2 级同步只保证电平合法、**不保证采到的是边沿前还是边沿后的值**；当数据跳变沿落在 ref 采样沿附近时，`d_s1` 采到的 nibble 是旧值或新值不可控。
2. **边沿检测有 ±1 ref 周期抖动**（`tck_sync` 同步链），而数据用的是**另一条独立同步链**（`d_s0/d_s1`）——**时钟路径和数据路径的同步延迟不等且各自抖动**，导致 "edge + EYE_DELAY" 这个 latch 时刻相对真实数据眼图的位置**逐边沿漂移**。

这两条都**与频率无关**（所以降频 /64→/128 不改善）、**与 EYE_DELAY 无关**（所以 EYE 4/8/16/38/64 都 ~8%）、**与单/多 lane 无关**（所以四 lane 误码相同）——**蓝方观察到的全部"已排除"现象，恰恰都是这个架构缺陷的预期表现**，而蓝方把它们当成了排除 a 的证据。这是核心逻辑谬误。

**最该做的不是再调参数，是换采样架构**（用 ref 域同步 TRACECLK 的边沿去 enable 一个对数据的"同时刻"采样，消除时钟链/数据链的差分延迟；或干脆回到 IDDR + 正确相位）。

## 一、`sim 100% = RTL 正确` —— 致命的伪证据

### 蓝方主张
"RTL 逻辑正确，因为 sim 把 LA 真实波形全量灌入做到逐字节 0 失配。"

### 红方拆解：这个 sim 在结构上验证不了任何异步采样问题

读 `xil_stubs.v` + `tb_dsl_replay.v`，列出 sim **结构上无法覆盖**的真实效应：

| 真实效应 | sim 里的状态 | 为什么覆盖不了 |
|---|---|---|
| TRACECLK 与 ref_200m 的真实相位关系 | TB 用 `#20`（20ns 栅格）驱动 pin，ref 用 `#2.5` | 两者在仿真里是**理想对齐的离散事件**，相位关系是固定整数比，不游走 |
| 数据相对时钟的 skew | 0（TB 同一个 `#20` 同时更新 clk 和 data） | TB 里 data 和 clk **同一时刻**变，永远没有 skew |
| IDELAYE2 真实延迟 | `assign DATAOUT = IDATAIN`（零延迟直通） | tap=16 的 ~1.25ns 延迟在 sim 里**不存在** |
| 时钟树插入延迟 / 抖动 | BUFG/BUFIO/BUFR 全 `assign O=I` | 插入延迟、jitter、skew 全为 0 |
| **异步采样亚稳态** | iverilog 2-state，`d_s0<=data_dly` 在理想对齐栅格上永不"踩沿" | **仿真器不建模亚稳态；且 TB 的 20ns 栅格与 5ns ref 栅格是 4:1 整数比，data 跳变永远落在 ref 沿的固定相对位置，永不落进采样孔** |
| TRACECLK 边沿质量（振铃/慢沿/反射） | pin 是理想方波 | TB 喂的是 0/1 离散样本，没有模拟边沿 |

**关键结构性缺陷**：TB 把 LA 的 **50MSa/s 离散样本**（已经是"每 20ns 一个干净 0/1"）当激励，ref_200m 是 5ns。**20ns 是 5ns 的整数倍**——所以在整个 sim 里，TRACECLK 的每次跳变都恰好落在某个 ref 沿上、且每次的相对相位完全相同。**真实板上 TRACECLK 与 MMCM 出的 ref_200m 是两个无关晶振源，相位连续游走、且数据跳变会以各种相位扫过 ref 采样窗口。** sim 的整数比栅格**在结构上排除了**这种相位扫描，因此**永远不可能复现"数据跳变落在采样孔导致亚稳态/采错值"**。

### 裁决
🔴 **致命逻辑谬误**。"sim 逐字节 0 失配"只证明了**一件事**：在"数据已经被 LA 干净离散化、且与 ref 理想整数比对齐"的前提下，OVERSAMPLE 的**配对/组帧逻辑**（哪个 nibble 进 a、哪个进 b、字节怎么拼）是对的。它**完全没有、也不可能**验证真实异步采样的相位/亚稳态/skew。**蓝方拿它当"RTL 正确"于是去别处找原因——这一步把侦查方向从一开始就带偏了。** 真正没被验证的恰恰是 sim 跳过的那一整类效应。

## 二、"四 lane 误码相同 ⇒ 不是 SI" —— 偷换概念

### 蓝方主张
排除 SI，因为没有单条坏线。

### 红方拆解
这是用**排除"单线 SI"**冒充**排除"SI"**。共模 SI——地弹、面包板/杜邦线共用回流路径差、TRACECLK 自身振铃、参考地不干净——**恰恰会让四条 lane 同时、同等地出错**。蓝方的实验设计（比四条 lane 的误码率）对共模失效**没有分辨力**：共模 SI 的签名就是"四 lane 一致"，与蓝方观察到的现象**完全吻合**，所以"四 lane 相同"不能排除 SI，反而**与共模 SI 一致**。

但是——**注意**：14 文档 §1 接线是"杜邦线 + 共地 + 面包板"，这本身是共模 SI 的高风险接法。**不过**，下面三/四会论证：8% 在 1.3MHz 这种 380ns 半位的巨大眼图下，**SI 不太可能是主因**（边沿再脏，380ns 眼图也足够宽），所以这条虽然是逻辑谬误，但 SI **大概率不是真凶**——真凶在采样架构（见总裁决）。**红方在这点上不替蓝方翻案"是SI"，但要指出"用四lane相同排除SI"这个推理本身无效。**

### 裁决
🟠 严重逻辑谬误（推理无效），但结论（非 SI）可能凑巧对——理由错了。

## 三、采样架构硬伤（核心，致命）

### 硬伤 A：`d_s0 <= data_dly` 直接在 ref 域采异步数据，2 级同步不解决"采到哪个值"

```verilog
always @(posedge ref_200m) begin
    tck_sync <= {tck_sync[1:0], trace_clk_ibuf};
    d_s0 <= data_dly;     // ← 异步数据直接进 ref 域
    d_s1 <= d_s0;
end
```

`data_dly` 是异步的 TRACED（经 IDELAY，但仍异步于 ref_200m）。`d_s0 <= data_dly` 在 ref 沿采它：
- 2 级同步（d_s0→d_s1）保证 **d_s1 电平合法**（不亚稳）；
- **但不保证 d_s1 是数据跳变前的值还是跳变后的值**。当 TRACED 跳变沿落在 ref 采样沿的 setup/hold 窗口内，d_s0 可能采到旧值、新值、或亚稳后解析成任一值。

**这与频率无关**：每个数据 bit 跳变都有一个固定概率（≈ setup+hold 窗口 / ref 周期 = ~几百ps/5ns ≈ 5~15%）落进采样孔。**1.3MHz 还是 84MHz，每个跳变的中招概率一样**——**完美解释"降频不改善"**，且数量级（~15% nibble 错 → 字节级 ~8% 残留）**对得上 8%**。

### 硬伤 B：时钟链与数据链的同步延迟不等且独立抖动

- TRACECLK 边沿经 `tck_sync[2:0]`（3 级）检测，`rise_evt = tck_s & ~tck_prev` 用的是 **bit[2] 和 bit[1]**；
- 数据经 `d_s0/d_s1`（2 级）；
- 两条链**级数不同、各自有 ±1 ref 周期的同步不确定性**。

于是 "检测到边沿后等 EYE_DELAY 再 latch d_s1" 这个时刻，相对**真实数据眼图中心**的位置 = (边沿检测延迟 ± 1) − (数据同步延迟 ± 1) + EYE_DELAY，**抖动 ±1~2 个 ref 周期（±5~10ns）**，且因 TRACECLK/ref 相位游走而**逐边沿变化**。在 1.3MHz（眼图 380ns）下这点抖动不致命，**但它叠加在硬伤 A 上**——硬伤 A 才是 8% 的主源。

### 硬伤 C（次要）：`f_arm`/`r_arm` 计数器在边沿间隔 < EYE_DELAY 时的行为
若边沿检测**误判**（多检/漏检，例如 TRACECLK 振铃在 ref 域被 `tck_sync` 采成多个跳变），`rise_evt` 在 arm 未完成时再次置位会**重置 r_cnt 重新计时**，导致这一周期 latch 时刻错乱或漏 latch。这在边沿质量差时会贡献额外错误，但属次要。

### 为什么这套架构错（本质）
OVERSAMPLE 的本意是"像 LA 一样 mid-eye 采样"。但 **LA 是单一时钟域**：它用自己的 50MSa/s 时钟同时采 clk 和 data，clk 和 data 经历**完全相同**的采样链，相位关系被一致地量化。而这里的 RTL **把 TRACECLK 边沿检测和数据采样放在两条独立的同步链**，再用"边沿+延迟"去对齐——**等于人为制造了 LA 没有的时钟/数据差分延迟**，并把异步数据的采样孔问题（硬伤 A）原样保留。**sim 复现不了，正因为 sim 里 clk 和 data 是理想整数比对齐的。**

### 裁决
🔴 致命。这是 8% 的最可能根因，且 sim 结构性盲区正好盖住它。

## 四、"EYE 全 8%、降频不改善 ⇒ 排除相位" —— 解释不全

### 红方拆解
蓝方用"EYE 扫描和降频都不改善"推"不是相位问题"。但**硬伤 A（异步采样孔）的签名恰恰就是"EYE 无关 + 频率无关"**：
- EYE_DELAY 改的是 latch 时刻在**半位内**的位置，而硬伤 A 的错误发生在**数据进 ref 域的那一刻（d_s0）**，发生在 EYE 逻辑之前——**所以调 EYE 当然不改善**；
- 频率无关已在硬伤 A 解释。

所以"EYE/降频不改善"**不能排除相位/采样问题**，它**正是采样孔架构缺陷的指纹**。蓝方又一次把"缺陷的预期表现"读成了"排除缺陷的证据"。

蓝方提的"TRACECLK 边沿质量差导致边沿误判"（硬伤 C 方向）也确实 EYE/频率无关——**和硬伤 A 一样无法靠 EYE/降频区分**。要区分必须用下面五的实验。

### 裁决
🟠 严重。三个不同根因（硬伤A采样孔 / 硬伤C边沿误判 / 共模SI）**都**产生"EYE无关+频率无关+四lane一致"，蓝方的实验**对这三者没有任何分辨力**，却用它们排除了相位。

## 五、"误码随相位拍频游走" —— 推断还是测量？

### 红方拆解
14 文档/蓝方说"干净段位置每次 re-arm 随机 ⇒ 相位拍频"。这是**推断，不是测量**——没有同时记录 TRACECLK/ref 相位。"某段干净某段脏、位置随机"有**多个**同样成立的解释，蓝方只选了拍频：

1. **硬伤 A 采样孔**：数据跳变相对 ref 沿的相位随两晶振漂移而游走 → 中招的 bit 位置随机 → 干净段随机。**与"拍频"现象一致，但根因是采样孔不是 EYE 相位**。
2. **cap_valid 偶发双脉冲/漏脉冲**：`b_latched <= (f_arm && f_cnt==0)` 这个推断 b_reg latch 时刻的逻辑，若 f_arm 计数被硬伤 C 干扰，会偶发多发/漏发 cap_valid → 字节流错位 → 整段脏。
3. **IDELAYCTRL/MMCM 未 ready 窗口、BRAM 写指针边界**：re-arm 时序窗口随机。

蓝方没有任何**直接证据**指向拍频而非 1/2/3。

### 裁决
🟠 严重。"拍频"是未经测量的归因，且与采样孔缺陷的现象无法区分。

## 六、约束文件审查（`trace_stream.xdc`）

发现几个真问题：

1. **`set_clock_groups -asynchronous` 把 `trace_clk_in` 与所有 MMCM 时钟设为异步** —— 这对 OVERSAMPLE 是**对的**（数据本来就要跨进 ref 域），但它**关闭了 Vivado 对 trace_clk_in→ref 域所有路径的时序检查**。于是硬伤 A/B 的采样路径**完全不被 STA 看管**，工具可以随便布线、插任意延迟——**缺约束让采样窗口被破坏的可能性存在且不可见**。
2. **`CLOCK_DEDICATED_ROUTE FALSE` on trace_clk_ibuf** —— 蓝方注释说"trace_clk 慢 /16，次优路由没关系"。但 OVERSAMPLE 模式下 **trace_clk_ibuf 同时喂 `tck_sync`（边沿检测）和（BUFR_IO 时）BUFIO**。次优路由会给 trace_clk_ibuf **额外插入延迟**，而 `d_s0` 走的是另一条 IDELAY+fabric 路径——**人为加大硬伤 B 的时钟/数据差分延迟**。这条约束在"凑合让它布通"的同时，可能正在恶化采样对齐。
3. **TRACECLK 当成 10ns 周期时钟约束**（实际 ~760ns），过严但无害于功能；真正问题是**没有任何约束描述 data 相对 trace_clk 的输入关系**（OVERSAMPLE 不走 IDDR 所以也没法用 set_input_delay 那套）——意味着**采样质量完全靠运气，没有任何时序契约**。

### 裁决
🟠 严重。约束没有为 OVERSAMPLE 的异步采样建立任何时序契约，硬伤 A/B 在 STA 盲区里。

## 七、测量方法学（最该先修的程序问题）

蓝方全程拿"板上 capture"和"**不同会话**的 LA 金标准"比，靠模糊对齐。**这使"per-lane 错误率""clean run 长度""相位拍频"全部不可信**——不同会话跑的是不同的程序时间点、不同的 re-arm，根本没有逐字节可对齐的 ground truth。基于不可对齐数据得出的所有定量结论（包括 8% 这个数字本身的构成）都站不住。

**正确做法（拿可对齐 ground truth）**：**LA 和 FPGA 同时打到同一根 trace 线、同一次运行同时抓**。LA 50MSa/s 抓引脚，FPGA 同时 CAP_RAW 抓自己采到的字节，事后用 TRACECLK 边沿序列对齐两者，**逐 nibble 比对**——这才能定位"FPGA 在第 N 个 TRACECLK 边沿采错了，而 LA 在同一边沿采对了"，把误码精确到具体边沿和当时的相位。

## 八、特别裁决：(a) 采样架构 / (b) 共模 SI / (c) 约束，谁更可能？

**判据 + 排序：(a) 采样架构亚稳态/采样孔 ≫ (c) 约束放大 > (b) 共模 SI。**

理由：
- **(b) SI 基本可排（但不是用蓝方的理由排的）**：1.3MHz、半位 380ns 的眼图巨大。即便杜邦线边沿振铃、慢沿，380ns 眼图中心仍极干净——SI 要在这么宽的眼图上造成 8% 稳定误码，需要持续到上百 ns 的振铃，物理上不合理。**所以 SI 不太可能是主因**（但"四 lane 相同"那条推理仍是无效的，见二）。
- **(a) 最可能**：硬伤 A（`d_s0` 异步采样孔）给出**频率无关、EYE无关、四lane一致、位置随相位游走**的全部签名，数量级（每跳变 5~15% → 字节 ~8%）也对得上。这是唯一能同时解释蓝方所有观察的根因。
- **(c) 放大而非主因**：缺时序契约 + CLOCK_DEDICATED_ROUTE FALSE 会**恶化** (a) 的差分延迟，但不是独立根因。

### 一次性区分 (a)/(b)/(c) 的确定性实验（不依赖跨会话 LA 对拍）

**实验 E1 —— 板内自源 + 同步采集（一锤定音）**：
- 用 **FPGA 自己的逻辑**在 ref_200m 域**生成**一个已知的、与 ref **同步**的伪 TRACECLK + 4-bit 数据（一个 LFSR/计数器），从 FPGA 输出脚出、用**短线/板内回环**接回 trace 输入脚，跑 OVERSAMPLE 采集，比对发出 vs 采到。
  - **若 0 误码** → 采集逻辑在"时钟与数据同源同步"时正确 → 证明 (a) 的逻辑本身没错，问题在**异步**（真实 STM32 时钟与 ref 无关）→ 锁定"异步采样孔/CDC"为根因（即硬伤 A 必须靠架构修，不是参数）。
  - **若仍有误码** → 问题在采集逻辑/约束本身（(c) 或逻辑 bug），与异步无关。
- 关键：这个实验**时钟与数据同源**，所以**消除了硬伤 A 的异步性**。它把"异步导致"和"逻辑/约束导致"一刀切开。

**实验 E2 —— 把 STM32 TRACECLK 直接当 FPGA 采样时钟（验证架构假设）**：
- 改 RTL：不用 ref_200m 过采，而是把 TRACECLK 经 BUFG/BUFR 当**真正的采样时钟**，用 IDDR 在 TRACECLK 边沿采数据（即 IDDR 模式），**但配合正确相位**（IDELAY 把数据移到 TRACECLK 边沿的眼图中心，因为 edge-aligned 源要把采样点移到半位中心）。
  - **若 IDDR + 正确 IDELAY 相位下误码骤降** → 坐实"ref 域异步过采架构"(a) 是病根，源同步采样（数据和时钟同域）才是对的。
  - 这也直接回应蓝方注释里"IDDR 对 edge-aligned 错"的判断——**IDDR 本身不错，错的是没把采样相位移到眼心**；用 IDELAY 移半个 UI（~190ns @1.3MHz 需要的 tap 远超 31，所以低速下要用时钟反相或计数分频，但高速下 IDELAY 够）即可。

**实验 E3 —— 同会话双抓对齐（拿可对齐 ground truth）**：见七。用于在 E1/E2 之后**量化**残留误码并定位到具体边沿。

**优先级**：先做 **E1**（板内同源回环）——它用最小改动、确定性地回答"是不是异步采样架构的锅"。E1 结果基本就能在 (a) 与 (c) 之间一锤定音。

## 九、未验证前提 / 谬误清单（分级）

**致命**
- F1：`sim 逐字节0失配 ⇒ RTL正确`——sim 结构上（整数比栅格 + 行为级直通桩 + 2-state）不可能复现异步采样/相位/skew/亚稳态，是伪证据。
- F2：`d_s0 <= data_dly` 异步采样孔 + 时钟链/数据链差分延迟（硬伤 A/B）= 8% 最可能根因，从未被质疑。

**严重**
- S1：用"无单线坏 lane"排除 SI（共模 SI 签名正是四 lane 一致）——推理无效。
- S2：用"EYE/降频不改善"排除相位——这恰是采样孔缺陷的指纹，无分辨力。
- S3："相位拍频"是推断非测量，与采样孔/cap_valid 异常/ready 窗口不可区分。
- S4：xdc 对 OVERSAMPLE 异步采样路径无任何时序契约（set_clock_groups 关检查 + CLOCK_DEDICATED_ROUTE FALSE 放大差分延迟）。
- S5：测量方法学全靠跨会话模糊对齐，定量结论不可信。

**次要**
- m1：边沿间隔 < EYE_DELAY / TRACECLK 振铃被 tck_sync 采成多沿 → r_cnt/f_cnt 重置错乱（硬伤 C）。
- m2：MMCM jitter / 200MHz 对 1.3MHz 的相位量化（76 周期/半位）——量化够细，**不是**主因（蓝方若怀疑这个是又一次找错方向）。

---

## 十、一句话结论

**蓝方打了多轮地鼠，是因为第一块多米诺骨牌就倒错了方向：那个"逐字节 0 失配"的 sim，用的是 50MSa/s 离散样本（与 ref_200m 成整数比）+ 全直通行为级桩 + 2-state 仿真器——它在结构上根本不可能复现真实的异步相位游走、skew 和采样亚稳态，所以它证明的只是"nibble 配对/组帧逻辑对"，绝不是"RTL 采样正确"。被这个伪证据导向后，蓝方在 SI/EYE/降频/拍频上反复排查，而这些实验对真正的病根——`d_s0 <= data_dly` 在 ref 域直接采异步数据的采样孔（叠加时钟链与数据链不等的同步延迟）——全都没有分辨力（采样孔的签名恰好就是"频率无关、EYE无关、四lane一致、位置随相位游走"，蓝方把缺陷的预期表现一条条当成了排除它的证据）。在 380ns 眼图下还有 8% 稳定误码，SI 物理上不合理，最可能是 (a) 异步过采架构缺陷。一次性判定实验：E1 板内同源回环（FPGA 自生与 ref 同步的伪 trace 回环采）——若 0 误码就锁定异步采样是病根，必须改架构（源同步 IDDR + IDELAY 移眼心，E2 验证），而不是继续调 EYE/tap/降频。**
