# r17 · 提案 15「SWO 单线 trace 移植」对抗性评审

> 评审对象：`proposals/15-swo单线trace采集移植方案.md`
> 立场：红方，严格证伪。配套已读：上游 `orbtrace/trace/swo.py` 全文、`trace_capture_a7.v`（OVERSAMPLE 现状）、r12–r16 并口 SI 调查链。
> 原则：不接受"复用度极高/工作量小/风险低"这类自我说服话术，逐条要数据/实验。

---

## 总裁决（先给结论）

**提案该「改」并「降级」，不该按当前"强烈建议优先移植"的姿态执行。**

提案有一个**真价值**和一个**被自己埋掉的致命矛盾**：

- **真价值**：SWO 确实消除并口的**源同步 + 通道 skew + 独立时钟线**这三类 SI（这是物理事实，成立）。作为"全链路（下游解码/时间戳/Perfetto）的低风险端到端验证载体"，它有用。
- **致命矛盾**：提案在第 7 节亲口说"SWO 当**并口的黄金对照基线**"——但**SWO 必须 stall 节流、并口主线的存在理由恰恰是满速不可 stall 实时**。两者的 CPU 执行时序、trace 数据量、丢包行为**根本不同**，**SWO 解出的指令流不能当并口满速场景的 ground truth**。LA 才是金标准，而 LA 已经有了。**所以 SWO 既当不了主线对照基线，又没解决主线命门——它是一条独立的、能力受限的旁路。**

更尖锐的一点：**提案是在用一个月的移植，绕过一个"重插排线 + per-lane 边沿探测"几天就能定位的物理接触问题**（r16 的双峰/频率相关现象 + 本提案自述"怀疑重启动到了排线"）。在并口 SI 被证伪为"不可解"之前转 SWO，是逃避，不是推进。

判断：**先花 3–5 天把并口 SI 钉死（证实或证伪"重启动排线/接触"假设）。SWO 作为下游验证载体可以并行小投入做仿真（阶段 A），但不授权"优先级高于并口 SI 定位"。**

## 逐条质疑

### Q1 核心假设：「SWO 把并口最难的 SI 整类消除」

【结论：**部分成立，但偷换了"消除一类"与"无新坑"**】

**成立的部分**：单线确实没有 skew、没有源同步 setup/hold、没有独立时钟线质量问题。这是物理事实。

**被掩盖的部分——SWO 在我们这块板上有它自己的采样坑，提案用一句"过采样 100×、眼图极宽"带过**：
1. **PB3 走线 / 共地 / 杜邦线**：SWO 不是没有 SI，是没有**通道间** SI。单线自身的反射、地弹、杜邦线寄生**照样存在**——而 r16 已经发现"重启后接触/SI 漂移"是当前并口的疑似病根，**同样的杜邦线接触问题在 SWO 单线上一样会发生**（只是少了 skew 维度）。提案把"少了 skew"说成"SI 整类消除"，**夸大了**。
2. **过采样亚稳态**：SWO 异步进 ref_200m，`swo_pulse_capture` 的 3-FF 同步 + 翻转检测，与并口 OVERSAMPLE 是**同一套异步采样架构**——r15/r16 反复质疑的"异步数据采样孔 / 同步链抖动"在 SWO 上**结构相同**。100× 过采样让眼图宽到这些问题大概率不致命，但"大概率"不是"消除"。
3. **毛刺**：上游 `PulseLengthCapture` 的 `0b010/0b101` case 只滤**单采样**毛刺。杜邦线上的多采样毛刺/振铃它**不滤**。

**最低成本证伪/证实**：
- **不写任何 RTL**，先用现有 LA（已是金标准）抓 PB3 的 SWO 波形，看单线在你这套杜邦线 + 共地接法下边沿/眼图是否真"极宽极干净"。若 PB3 在重启后也出现类似并口的边沿漂移 → SWO 没绕开物理接触问题，核心假设证伪。**成本：1 次 LA 抓取，0 RTL。**

### Q2 「复用度极高 / 工作量小（~150 行）」的水分

【结论：**RTL 行数大致可信，但"下游零改动 + 从 duty 逻辑改出 PulseCapture"被高估**】

读了上游 `swo.py`，三个 NRZ 模块（PulseLengthCapture ~40 行 + NRZDecoder ~20 行 + UARTDecoder ~25 行）本身确实小。**但提案的三处乐观要点破：**

1. **「PulseLengthCapture 可从现有 duty 逻辑改出来」——证伪**。读上游实现：`PulseLengthCapture` 的核心是一个 **3-bit state = 2bit过采样历史**的 Switch 表（`000/111`→+2、`011/100`→output_0、`001/110`→output_1、`010/101`→毛刺并入），它做的是**每周期吃 2 个过采样**、带半采样相位的脉宽量化 + 毛刺合并。我们 `trace_capture_a7.v` 的 `dwell`/`duty_hi_sum` 是**测时钟占空比的简单计数器**，没有 2-sample/cycle 结构、没有 output_0/output_1 的半采样边界逻辑、没有毛刺并入。**"改出来"约等于照上游重写，不是改 duty 逻辑。** 提案这句是自我说服。
2. **「字节流格式一致、下游零改动」——存疑，必须验**。提案断言 SWO 和并口"下游字节流格式一致（都是 TPIU formatter 帧）"。**但这取决于 STM32 侧 TPIU 配置**：SWO 路径若 `TPIU_SPPR=2`(NRZ) 且 `FFCR` formatter on，**理论上**也出 formatter 帧；但 SWO 常见用法是**单通道、formatter 关**（直接 ITM/ETM 字节）。**两条路的字节流是否真同构，没有实测证据，只有"理论上"**。若 SWO 下 formatter 行为不同（如半同步 idle 模式、单通道无 frame），`etm35lib` 的 TPIU 去帧分支可能要改。提案把"零改动"当既成事实。
3. **被低估的集成点**：
   - **bitlen CSR**：NRZ 要运行时设波特率（提案自己说做成 CSR），这要动现有 CSR 译码 + 上位机配置流程，不是零。
   - **时钟域**：SWO 字节在 ref_200m 域产生，与现有 BRAM 写路径（clk200, cap_valid）一致——这点**确实可复用**，提案对。
   - **NRZDecoder 的 acc 位宽/bitlen 半位偏置**（`(count<<4)+(bitlen>>1)`）：定点实现细节，照搬要小心溢出，单测必须覆盖。

**最低成本证实**：阶段 A 仿真时，**直接搬上游 `test_swo.py` 的向量**当 testbench 期望值（提案也这么说）——这能证实三个模块 RTL 等价。**但"下游零改动"必须用一段真实 SWO 字节流（支线 LA 抓的）喂现有 `etm35lib` 跑通才算数**，不能靠"理论同构"。成本：复用现有向量，0.5 天。

### Q3 带宽天花板是否致命 / 能否当「黄金对照基线」

【结论：**当下游验证载体——成立；当并口满速对照基线——证伪**】

这是提案**最该被打的自相矛盾**。

- 提案 §5 自承认：满速 ETM 需 **stall 节流**，SWO NRZ 实用 ~6MHz（CH343 实测），FPGA 侧理论高些但"满速 ETM 仍需 stall"。
- 提案 §7 又说：SWO 解出的指令流当 **ground truth**，并口数据与之逐函数比对，判定并口 SI 是否采对。

**这两条不能同时成立**：
1. **stall 改变了被测程序的执行**：开 stall 后 CPU 在 trace FIFO 满时**暂停**，指令时序、中断时序、RTOS 调度全被改变。**SWO（stall）跑出来的执行流 ≠ 并口（满速无 stall）跑出来的执行流**。拿一个被 stall 扰动的执行序列当"满速并口"的对照，**逻辑上无效**。
2. **真实负载下更糟**：proj_add 这种玩具循环 stall 影响小；一上 LVGL/RTOS，SWO 带宽（~2MHz NRZ = 250KB/s 量级）**远扛不住满速 ETM**（并口满速 4bit×2×TRACECLK 是几十~上百 Mbit/s），stall 会**频繁触发甚至丢包**，SWO 看到的是"被严重节流的、断断续续的"执行流——**作为参考价值极低**。
3. **更要命：金标准已经有了**。LA 已经能 0.002% 解出并口真实 PC（提案 §1.1 自己引用）。**要对照基线，LA 就是**，且 LA 抓的是**满速并口同一根线**、零 stall、与并口完全同源。**SWO 既不同源（不同引脚、不同 TPIU 配置）、又不同状态（stall vs 满速），凭什么比 LA 更适合当对照基线？** 提案给 SWO 安的"黄金对照基线"角色，**LA 已经占了且更合格**。

**最低成本证伪**：不需要做 SWO。直接问——"并口满速场景，你已经有 LA 金标准能 0.002% 解，为什么还需要 SWO 当对照？" 如果答不出 SWO 比 LA 更优的对照价值，§7 的核心卖点就空了。

### Q4 是不是在逃避真问题（并口 SI 可能只是排线接触）

【结论：**高度存疑——提案在并口 SI 未穷尽定位前就跳走**】

提案 §1.1 自述：「**怀疑重启动到了排线**」、duty 测量显示「LOW 半位 155–385ns（下降沿位置异常）」。结合 r16 的双峰/频率相关结论——**这强烈像物理接触/排线问题，不是不可解的架构问题**。而提案没有证据表明已穷尽下面这些**几天就能做完**的并口 SI 定位：

1. **重插/换排线**：最便宜的实验。提案自己怀疑"动到排线"，**那就重插紧、换一根新排线、缩短长度，重测**。若 unknown 从 15% 掉下去 → 病根是接触，**SWO 移植整个不必要**。成本：10 分钟。
2. **示波器/LA 看 FPGA 输入脚（不是探头点）的 TRACECLK**：r16 已指出"LA 测探头点 ≠ FPGA 脚"。直接探 FPGA 输入脚的 TRACECLK 下降沿，看 155ns 那个失真是真实信号还是 FPGA 输入级/采样问题。成本：1 次示波器。
3. **per-lane 边沿质量探测**：r16 的 E0（同会话 LA+FPGA 逐 nibble diff 按 lane 分类）还没做。**这张图直接告诉你是某条 lane 坏还是共模**。成本：扩一个解析脚本。

**这是核心指控**：提案把"并口 SI"当成一个需要绕开的不可解命门，**但它自己的证据（'怀疑动到排线' + LOW半位失真 + 频率相关）全部指向物理接触/信号质量这种可定位、可能可修的问题**。在重插排线 + 示波器看脚 + per-lane diff 这三个低成本实验做完之前，"SI 不可解所以转 SWO"是**未证结论 + 逃避**。

---

### Q5 支线结论从 LA 路径迁移到 FPGA 过采样路径的断层

【结论：**存在未验证断层，提案用"支线已跑通"掩盖了"支线不是用 FPGA 跑的"**】

提案反复引用支线"0.002% 命中真实 PC"作为信心来源。**但支线是 LA + CH343 + J-Link 验证的，不是 FPGA 过采样**。迁移到 FPGA 的未验证断层：

1. **定频要求**：NRZ 异步，CPU 变频失锁（支线 §7 最大坑）。FPGA 实现里 `bitlen` 是固定 CSR 值——**CPU 一变频，FPGA 的 NRZDecoder 立刻失锁**，和支线一样。提案说"定频 168MHz 即可"，但这意味着**这套工具只能在定频下用**，LVGL/RTOS 真实场景若有动态调频（PLL/低功耗），直接废。这个约束提案轻描淡写。
2. **stall 死锁在 FPGA 侧的新形式**：支线 §7.2 的 stall 死锁（SWO 没输出→FIFO 满→CPU 卡死）在 FPGA 实现里依然存在，且 FPGA 这边的 BRAM one-shot + re-arm 逻辑（r16 的双峰元凶嫌疑）可能引入**新的竞态**——SWO 字节流经过的也是同一套 re-arm/BRAM 路径。
3. **波特率失锁的 FPGA 表现**：CH343 失锁是丢字节；FPGA NRZDecoder 失锁是 `acc/bitlen` 错配，可能**静默出错字节**喂进解码——和并口"散落 nibble 错"异曲同工。

**最低成本证实**：阶段 A 仿真时，**故意喂 bitlen 偏移 ±5% 的脉宽流**，看 NRZDecoder 输出错多少——量化失锁敏感度。成本：仿真加一个 case。

### Q6 机会成本：现在该做 SWO 还是先钉死并口 SI

【结论：**先钉死并口 SI。SWO 不是主线推进，是能力受限的旁路**】

- **并口 SI 是主线命门**：提案 §7 自己承认"并口 trace 仍是满速、不可 stall 实时的最终目标"。满速实时是整个项目选 FPGA（而非买现成 SWO 探针/J-Link）的**存在理由**。SWO 2MHz 这点带宽，**J-Link / ST-Link 早就做到了，根本不需要自己移植到 Artix-7**。
- **如果并口 SI 攻不下，整个 FPGA 方案就没有意义**——那才是必须先回答的问题。转去做一个 J-Link 就能干的 SWO，是**回避对项目生死的回答**。
- **SWO 的正当用途**：作为下游（解码/时间戳/Perfetto）的**端到端连通性测试夹具**——用一个低 SI 的前端先把后端跑顺。这有价值，**但它是测试基建，不是产品能力，优先级低于并口 SI 定位**。

## 总评：执行 / 改 / 砍

**判定：改 + 降级。不砍（有真价值），但坚决反对"优先移植/当并口黄金基线"的当前定位。**

**正确的做法（按顺序）**：
1. **先做 3 个并口 SI 定位实验（共 ~3–5 天，0 移植）**：① 重插/换/缩短排线重测 unknown；② 示波器/LA 探 **FPGA 输入脚**的 TRACECLK 下降沿（验证 155ns 失真在不在脚上）；③ r16 的 E0 同会话 LA+FPGA 逐 nibble per-lane diff。**这三个直接判定并口 SI 是"接触可修"还是"架构难解"。**
2. **若并口 SI 是接触问题（很可能）**→ 修好，主线继续，SWO 移植**不必要**。
3. **若并口 SI 确认架构难解**→ 此时 SWO 作为**下游验证夹具**（不是对照基线）有价值，可做阶段 A 仿真；但要同时承认"满速实时这个项目目标可能要重新评估"。
4. **无论如何，删掉提案 §7 "SWO 当并口黄金对照基线"的说法**——LA 已是更合格的金标准，这个角色是自我说服。

**结论反转的前提**：
- 若 Q4 的三个实验证明**并口 SI 是无法用接触/换线/换板解决的架构性命门**，且项目**接受降级为"非满速、可 stall 的 trace 工具"**——那么 SWO 从"旁路"升级为"主路"，提案该执行（但那时项目定位已经变了，要诚实承认满速实时目标放弃）。
- 若实测发现 **SWO 在你的杜邦线上重启后也漂移**（Q1 实验）——提案直接砍，因为它连"低 SI"这个唯一卖点都不成立。

## 点破自我说服处（直接说）

1. **"工作量小、风险低、复用度极高"——这是结论先行**。提案开头就下了"可行且工作量小"的判词，再逐条找证据支持它。PulseCapture"从 duty 改出"、字节流"格式一致零改动"都是没验证就当成立的乐观假设。
2. **"SWO 当并口黄金对照基线"——最大的自我说服**。它让 SWO 显得"不只是旁路，还服务主线"，但 stall ≠ 满速、SWO 源 ≠ 并口源，这个角色逻辑上不成立，且 LA 已经占了。**这条是为了让"转 SWO"显得不像逃避而硬安的价值。**
3. **用支线"0.002% 命中"反复背书 FPGA 移植**——但支线是 LA 路径，不是 FPGA 过采样。**借另一条路的成功，给本路径的未验证部分贴金。**
4. **回避了最便宜的实验**：自己写"怀疑动到排线"，却不先花 10 分钟重插排线，而是规划一个月的移植。**这是最明显的"宁愿做有趣的新工作，也不做无聊的物理排查"的工程师本能**——红方直接点破。
