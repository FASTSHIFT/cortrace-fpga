# r28 响应 — R1 区分实验（解码盲推 vs 采集丢锚点）

**日期**：2026-07-19
**回应**：r28 红方 R1（"0 字节错 ⇒ 采集无误"证伪；要求区分 BB-OFF+cache 假调用是解码盲推还是采集丢锚点）
**立场**：接受红方 R1，本文用实测区分，不再拿字节错判据当采集无误的证明。

## 前置：固件 vs ELF 一致性核对（红方严谨性要求）

R1 分析的基准 ELF 必须与 flash 实跑固件一致，否则"合法目标集"是错的。
- `arm-none-eabi-objcopy` 从 `/tmp/stm32h743_cache.elf` 生成 bin，openocd `dump_image` 读
  flash 同长度 44524 B，`cmp`：**仅 12 字节不同**，全部是段间隙填充（.isr_vector 尾
  @0x298 的 8 字节 + @0xa4dc 的 4 字节，ELF=0x00 vs flash=0xFF 擦除值），**所有代码/数据
  字节一致**。→ flash 固件 == cache ELF（`-O3+cache`，含 SCB_EnableICache），基准可信。

## R1 实验（纯软件，零上板）：采集的地址锚点是否干净

BB-OFF + cache 抓样 `/tmp/cache_bb0.bin`，OpenCSD 解码：

- **包构成**：I_ATOM 共 ~3200 个（F3=618/F5=1902/F6=516...），**真实地址包仅 13 个**
  （I_ADDR_S_IS1 / I_ADDR_L / I_ADDR_CTXT）。I_ADDR_MATCH 148 个是解码器自推的精确匹配，
  非采集新锚点。**≈3200 atom / 13 地址锚点 = 每锚点盲推 ~250 个分支**——极稀疏。
- **关键判据（红方 R1）**：13 个采集给出的绝对地址锚点，**全部 13/13 落在 ELF 合法 .text
  指令区**（0x80002a0-0x800a4dc），无一脏地址（如 0x08007b56/0x08007f00 均为合法指令地址）。

### R1 阶段结论
- **排除"采集把地址包采错/采脏"这一失效模式**：采集给的 13 个绝对地址锚点全干净、全落
  合法指令区。这是红方担心的最直接采集失效形式，**已证伪**（不是这种）。
- **假调用（core_list_init→HAL_UART_Init）指向盲推**：HAL_UART_Init@0x791c 不在 139 个
  ELF 合法 BL/BLX 目标集内，但它是解码器在稀疏锚点间**顺 ELF 盲推越过函数边界**落进物理
  相邻函数的结果，不是某个地址包被采成了 0x791c。
- **仍未排除的采集失效（红方 R1 残留）**：地址锚点干净 ≠ atom 流完整。若采集在高速 cache
  流下**丢了 atom 字节**（E/N 序列错位），盲推照样走偏且不产生非法包、不脏地址锚点。
  这需要红方实验 3（BB=1+cache 降频得 ground truth）进一步区分：BB=1 每分支显式地址、
  不靠 atom 盲推，若 BB=1 干净而 BB-OFF 走偏，则差异来自盲推模型而非采集丢字节（采集对两
  配置一致）。

## 实验 3（黄金对照）：BB=1 不溢出 ground truth vs BB-OFF+cache

编 BB=1 + cache + **sysclk 降到 75M**（P=6，TRACECLK 仍 112.5M，实测 DIVR 确认
N=36/P=6/R=2）。75M 让 BB=1 生成率减半、不溢出，得干净 ground truth。

- **tap 选取教训（再次印证红方 r25）**：A-sync 数不是采集质量指标。clk=0/data=12 的
  A-sync=74 最多，但字节错 2.16%；clk=0/data=8 的 A-sync 少却字节错仅 **0.10%**——
  **用 RESERVED 字节错判据选点，不用 A-sync 数**。取 clk=0/data=8。
- **BB=1 75M（不溢出，字节错 0.10%，显式地址不盲推）调用图**：945 visit / 23 transition，
  **无一个 UART/HAL 假调用**——**干净**。
- **对照 BB-OFF+cache**：HAL_UART_Init 等假调用 ×22+。

### R1 最终裁决（回应红方）
两配置**采集前端完全相同**（同 FPGA、同 112.5M、同眼扫）。差异只在 BB：
- BB=1 每分支显式地址、不靠 atom 盲推 → 调用图干净。
- BB-OFF 靠 ~13 稀疏地址锚点 + ~3200 atom 盲推 → 走偏进相邻函数。

若走偏源于**采集丢字节**，则 BB=1 的 atom/地址流（更密、冗余更多）同样会受影响出假调用；
但 BB=1 **干净**。故 **走偏纯粹来自 BB-OFF 的盲推模型在 cache 稀疏锚点下的解码局限，
不是采集丢字节**。红方 R1 的两种失效模式中，**"采集丢/错锚点"证伪**（地址锚点 13/13 干净
+ BB=1 干净双重证据），**确认是"解码盲推误差"**。

**采集侧在 BB=1 下到 112.5M 干净可用（字节错 0.10%）这一点，用不依赖字节错判据的独立证据
（BB=1 调用图无假调用）坐实**——回应了红方"别拿字节错盲区当采集无误证明"。

### 对方案的影响
- R1 定性为盲推 → 红方候选 (b) range-filter / (a) 加密 A-sync 缩盲推跨度**方向有效**。
- 但 R3（追平满血不可达）仍需 R2 生成率真值 + 承认"函数级采样"定位。
- 下一步：R2 停核积分法测真实生成率；然后据 R1/R2/R3 定最终方向（大概率转"热点函数
  range-filter 采样式剖析"，放弃"全程无损追平满血"）。
